## 主要なデータソース

### 1. 東京都オープンデータカタログサイト（メイン）

| | |
|---|---|
| カタログ | https://catalog.data.metro.tokyo.lg.jp/dataset |
| ポータル | https://portal.data.metro.tokyo.lg.jp/ |
| 基盤 | **CKAN** |
| 規模 | **61組織・約3,500件・14カテゴリー** |

応募条件が「**東京都のオープンデータ等を活用予定であること**」なので、
**ここが起点**になります。

#### CKAN API

CKAN の標準APIでデータセット・リソース・組織のメタデータを取得できます。
一般的な CKAN のエンドポイントは以下（実際の挙動は要確認）：

```
# データセットの検索
https://catalog.data.metro.tokyo.lg.jp/api/3/action/package_search?q=<キーワード>&rows=20

# データセットの詳細（リソースのURLが取れる）
https://catalog.data.metro.tokyo.lg.jp/api/3/action/package_show?id=<データセットID>

# 組織の一覧
https://catalog.data.metro.tokyo.lg.jp/api/3/action/organization_list

# グループ（カテゴリ）の一覧
https://catalog.data.metro.tokyo.lg.jp/api/3/action/group_list
```

`package_search` でキーワードから当たりを付け、`package_show` で
実データ（CSV/JSON等）のURLを取る、という流れになります。

> 💡 **まずやること**：`package_search` を叩いて、候補テーマに関連する
> データセットが実在するかを確認する。アイデアが先行してデータが無い、
> というのが一番痛いパターンです。

#### カタログサイトで使える機能

公式トップページによると、カタログサイトには以下があります。

- **オープンデータの活用事例を一覧で検索できる**
  — 既存サービスとの差別化を考えるときに見ておく価値があります
- **オープンデータへのアクセスランキング**
  — **どのデータがよく使われているかが分かります。**
  人気データは使いやすい（＝形式が整っている）可能性が高い一方、
  他チームと被りやすいとも読めます。両面から見てください
- **必要なオープンデータのリクエスト送信**

もう一つ、**東京都オープンデータコミュニティ**があります。
利用者同士や都との繋がりを作る取り組みで、データについて相談できる場です。

### 2. 東京都オープンデータAPIカタログサイト

| | |
|---|---|
| URL | https://spec.api.metro.tokyo.lg.jp/ |
| 使い方 | https://spec.api.metro.tokyo.lg.jp/spec/usage |

JSON形式でデータを取得できるAPI。

- `limit` パラメータで取得レコード数を指定
- `column` パラメータで取得したい項目を絞り込み

CSVをダウンロードして加工するより、**APIで直接取れるならそちらの方が
「オープンデータの有効活用」として見せやすい**です。

> 高頻度・準リアルタイムデータ**です。他はすべて年次調査・一覧・統計。
> 閾値超過の通知（プッシュ型）や、運動していい時間帯の提案に使えます。
> **ただし本当に1分値がAPIで取れるか、更新頻度・認証・CORS を必ず検証してください。**

> 💡 **国・地域別外国人旅行者行動特性調査**は、国・地域ごとに行動特性が
> 分かれているデータです。多言語サービスを「翻訳」で終わらせず
> 「**どの国の人が何を求めるか**」で出し分ける根拠になります。
> LLM単体では作れないので、データ活用と技術力を両立させられます。

> 💡 **TOKYO WALKING MAP** は「健康・スポーツ」「交通・移動」「観光・国際交流」の
> **3カテゴリ**に登場します（子育て支援制度レジストリと並ぶ最頻出）。

> 💡 **都営バス・都営地下鉄オープンデータ**は GTFS 形式の可能性が高く、
> 経路探索に使える品質のデータです。8/18 の調査で形式を確認してください。
> **公共施設一覧** は「交通・移動」「観光・国際交流」の2カテゴリに登場します。

> 🔴 **子育て支援制度レジストリは3カテゴリ（生活／子ども・若者／デジタル）に登場**します。
> 最頻出のデータセットで、都が活用を強く推していると読めます。
> **データ活用賞を狙うならまず当たるべき**データです。

> 💡 **都立スポーツ施設一覧**は「健康・スポーツ」「社会参加・活躍」の2カテゴリに、
> **防犯ボランティア団体アンケート**は「防犯・安心」「福祉・地域共生」の2カテゴリに、
> **福祉事務所一覧**は「福祉・地域共生」「デジタル」の2カテゴリに登場します。
> **複数カテゴリに出るデータは都が推している**と読めます。

> ⚠️ **3Dデジタルマップはデータ量が大きい**はずです。ブラウザで扱えるか、
> どの範囲に絞るかを 8/18 のデータ調査で必ず検証してください。
> 技術的な見せ場になる一方、5日で扱いきれないリスクもあります。

> 💡 **子育て支援制度レジストリ**は「生活」「子ども・若者」の2カテゴリに登場します。
> 都が推している中核データなので、使う価値が高いはずです。

> 💡 **防災の5件はすべて地理空間データ**です。緯度経度や区域ポリゴンを持つため、
> **掛け合わせの相性が非常に良い**（例：地域危険度 × 避難所 × 給水拠点）。
> 地図ライブラリを使う前提なら `docs/05-tech.md` の MapLibre / Leaflet を参照。

✅ **全12カテゴリ・57テーマ分の関連データを収録完了。**

## データ選定のチェックリスト

候補を見つけたら、実装に入る前にこれを確認してください。
**当日に「使えなかった」と分かるのが最悪です。**

- [ ] **実際にダウンロード／API取得できるか**（リンク切れは普通にある）
- [ ] **形式**：CSV / JSON / GeoJSON / Excel / PDF
      — **PDFしか無いデータは5日では厳しい**
- [ ] **文字コード**：Shift_JIS のCSVが混ざっていることがある。UTF-8 変換が必要か
- [ ] **更新頻度**：年1回更新か、リアルタイムか
- [ ] **粒度**：都全体か、区市町村単位か、施設単位か
- [ ] **座標**：地図で使うなら緯度経度が入っているか。住所しか無いならジオコーディングが要る
- [ ] **ライセンス**：CC BY 4.0 か、それ以外か
- [ ] **CORS**：ブラウザから直接叩けるか。ダメなら Workers 経由でプロキシする
      （`docs/05-tech.md`）

## ライセンスと出典表記

東京都オープンデータカタログのデータは多くが **CC BY 4.0** ですが、
**データセットごとに異なります。必ず個別に確認してください。**

### 作品に必ず入れること

- 使用したデータセット名
- 提供元（東京都○○局 など）
- ライセンス表記
- 取得日（データが更新される場合）

**出典明記は大会の趣旨そのものであり、審査観点にも直結します。**
「オープンデータが有効に活用されているか」を見られる以上、
何をどう使ったかが分からない作品は評価されません。

### 記載例

```
出典：東京都オープンデータカタログサイト「〇〇データ」（東京都〇〇局）
      https://catalog.data.metro.tokyo.lg.jp/dataset/xxxxx
      CC BY 4.0 / 2026-08-XX 取得
```

## この環境での注意

ネットワークポリシーが **Trusted** のままだと、東京都のサイトには一切アクセス
できません。**Custom に変更してください**（`docs/07-team-workflow.md`）。

設定前でも作業を進めたい場合は、取得済みの CSV / JSON を `data/` に置いて
コミットすれば全員で共有できます。
