## 🔴 依頼3【本体】自治体別トレンドの推定と、予測区間への反映

### データが増えました

学童（分子）と公立小学校児童数（分母）の年次系列が、両方とも取れました。

```
data/processed/gakudou_stats_by_municipality_timeseries.csv   分子 6点
data/processed/children_by_municipality_timeseries.csv        分母 5点

重なる年次：2021-05-01 / 2022-05-01 / 2023-05-01 / 2024-05-01 / 2025-05-01
```

**r_latent を5時点で計算できます。** これまでは実質2点で、
「自治体別の傾きはノイズと区別できない」という理由から
都平均の1点（+0.84pt/年）を49自治体すべてに当てていました。**その制約が外れました。**

> 2026-05-01 の学童データも取得済みですが、**分母（児童数）が存在しない**ため使いません。
> 実績と推計を混ぜた系列で傾きを引くのは筋が悪いためです。

### 3-1. 型を足す（②が `src/types.ts` のオーナー）

🔴 **既存フィールドを消さないでください。** ③の画面と `sample.json` が壊れます。**追加**で。

```ts
// Muni に追加
/** 公立小学校児童数の年次系列。2021-05-01 〜 2025-05-01 の5点 */
childrenSeries?: { asOf: string; count: number }[];
```

`gakudo` は既に `{ asOf, clubs, registered, waiting }[]` なので**時点が増えるだけ**（型変更なし）。

`baseChildren` / `children2023` は**残してください**。
`childrenSeries` があればそちらを使い、無ければ従来どおり動く段階移行にします。
**`sample.json`（6自治体・`childrenSeries` 無し）でも壊れないことが条件**です。

### 3-2. 自治体別トレンドを最小二乗で引く

```
r_latent(m, t) = (registered(m,t) + waiting(m,t)) / children(m,t)
```

各自治体について、年（西暦の実数）を説明変数に単回帰：

```
b(m)   = 傾き（年あたりの率の変化。0.0084 ＝ +0.84pt/年）
se(m)  = 傾きの標準誤差（残差平方和から。5点なので自由度3）
ci(m)  = b(m) ± t(0.90, df) × se(m)   ← 片側10%。既存の p10/p90 の考え方に揃える
```

**両方の系列が揃っている時点だけを使ってください。** 欠測時点はスキップして残りの点で引く
（利島村のように、分母の行が立たない自治体があります）。
**有効点が3点未満なら傾きを引かず、3-3 のフォールバックへ。**

### 3-3. 引けない自治体のフォールバック

| 自治体 | 状況 | 扱い |
|---|---|---|
| **江戸川区** | 2024-05（351人）→ 2025-05（6,623人）で系列断絶。全児童対象の「すくすくスクール」を2025年から計上したため。**使えるのは1点だけ** | 🔴 **都平均（49自治体の傾きの中央値）にフォールバック＋注記** |
| 有効点3点未満のその他 | データ欠測 | 同上 |

既存の `isExcludedFromTrend`（`series-break` 判定）はそのまま使えます。
**`series-break` はトレンド推定からのみ除外。スコア計算には含める**——ここは変わりません。

### 3-4. 予測区間に、トレンドの不確かさを入れる 🔴 これが本体

現状の `demandBand`（`src/core/muniDetail.ts`）はこうです：

```ts
demandBand: { lo: band.lo * rTarget, hi: band.hi * rTarget }
```

**児童数の推計誤差しか入っていません。** ところが `docs/14-basic-design.md` §0-2 が
自分で書いているとおり、**モデルを支配しているのはトレンド**です。
支配的な不確実性が帯に入っていない状態で「予測区間」と呼ぶのは、
この作品の「測っていないことを測ったように書かない」に反します。

```
r_target(m,y) = clamp( r_latent(m,2025) + b(m)     × (y − 2025), 0, RATE_CAP )
r_lo(m,y)     = clamp( r_latent(m,2025) + ci_lo(m) × (y − 2025), 0, RATE_CAP )
r_hi(m,y)     = clamp( r_latent(m,2025) + ci_hi(m) × (y − 2025), 0, RATE_CAP )
```

- 🔴 **切片は 2025-05 の実測値を使ってください**（回帰の切片ではなく）。
  画面に出ている「いまの登録児童数・待機児童数」と整合します。**傾きだけ回帰から取る**
- `demand` / `gap` の帯を、児童数の誤差帯とトレンド信頼区間の**両方**から出す
- 合成方法は②に任せます（単純な掛け合わせでも二乗和平方根でも）。
  **どう合成したかを必ずコメントに残してください**
- **`gap` の帯が画面の一番大きい数字です**（S2 と詳細の「◯人分、足りない」）

**クリップは傾きではなく `r_target` にかけてください。** 傾きを直接クリップすると
「豊島区は本当に下降しているのか」という判断をコードに埋め込むことになります。

### 3-5. `measureTrend()` の拡張（既存の返り値は壊さない）

③の画面 S5 が `TREND.trend / n / rateFrom / rateTo / excluded` を使っています。
**このフィールドは残してください。** 追加で：

```ts
byMuni:  Map<string, { slope; se; ciLo; ciHi; nPoints; fallback: boolean }>
median:  number   // 49自治体の傾きの中央値（フォールバック用・画面表示用）
points:  number   // 実測に使った時点数（＝5）
```

**`DEFAULT_TREND = 0.0084` も更新してください。** 5点で引き直すと変わるはずです。
`src/core/constants.ts` のコメントに**何時点・何自治体から出した値か**を書き直すこと
（いまは「2023-05→2025-05・48自治体」）。

### 3-6【余力があれば・推奨】縮約推定

5点は多くありません。`se(m)` が大きい自治体は極端な傾きを出しがちです。

```
τ²   = max(0, var(b) − mean(se²))     // 分散分解
w(m) = τ² / (τ² + se(m)²)
b_shrunk(m) = w(m) × b(m) + (1 − w(m)) × b̄
```

**15〜20行**です。「**時点数が5しかないので、推定の不確かさに応じて都平均に寄せている**」と
説明でき、審査基準「技術要素に合理性がある」の加点になります。
**時間が無ければ飛ばして構いません。3-1〜3-5 が必須です。**

### 🔴 豊島区を特別扱いしないでください

```
登録児童数 2,535 → 2,831 → 2,823 → 2,582 → 2,506 → 2,516（2021→2026）
```

2点で引いていた頃の値 −1.82pt/年 は、2021-22の上昇を無視した誤りでした。
**下降自体は本物ですが、直線ではありません。**

→ **折れ線を当てたり、直近だけ使ったりしないでください。**
　 最小二乗で引けば非線形は残差に出て、**信頼区間が自動的に広がります。**
　 それが正しい表現です。特別扱いを1つ入れると、他の48自治体にも同じ判断が要ります。

```
'登録率は都の3時点データの実測どおり年 +0.84pt 上昇。…'
```

ところが **`measureTrend(DATA)` が実データから出す値は +0.81pt** です。
画面はスライダーの横に `+0.81pt` を表示するので、**説明文と表示が食い違って見えます。**

`trend15` の説明「実測（**+0.84pt**）の約1.8倍です」も同様です。

### 提案

**説明文から数字を落としてください。** すぐ横に実測値が表示されているので、
数字を二重に持つ意味がなく、持つ限り必ずずれます。

```ts
baseline:  '学童を使う子の割合は、都のデータから実測したとおりに上がると仮定。'
           + 'クラブ数は据え置き（何もしなければどうなるか）。'
trend15:   '共働き世帯の増加が、実測よりも速く進んだ場合。'
```

あわせて `label` の「**登録率**が年 +1.5pt 上がる」を、
画面の語彙に揃えて「**使う子の割合**が年 +1.5pt 上がる」にしてください
（③は画面側を「学童を使う子の割合」に統一済みです）。

## 依頼8 `DEFAULT_TREND` も実データとずれています

`src/core/constants.ts`：

```ts
export const DEFAULT_TREND = 0.0084;   // ← docs 由来のハードコード
```

`measureTrend(DATA)` が実データから出すのは **0.0081**（48自治体）です。
