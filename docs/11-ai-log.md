## 作品そのものにAIを組み込んだ場合（あれば）

実装にLLMを使ったなら、ここに**何をどう使ったか**を書いてください。
提出項目③にそのまま転記できます。

**3か所で使います**（詳細は [`docs/14-basic-design.md`](14-basic-design.md) §7）。

- **使ったモデル / サービス**：Cloudflare Workers AI（**Qwen3 30B FP8**・事務局提供）
- **何を処理させているか**：
  1. **様式不定CSVの読解ETL**（前処理で1回・プランをコミットして固定）
     — 先頭30行を渡し「ヘッダ行番号・列対応・ブロック分割・数値クリーニング規則」の
     **JSONプラン**を生成させ、決定論的パーサがそれを実行する
  2. **自然文シナリオ → 都の公式係数へのパラメータ変換**（実行時）
     — 「駅前に600戸のマンションが2028年完成」を、`25es_survey` の
     住宅種別×学年別児童発生率の**どれをどこに幾つ適用するか**に翻訳する
  3. **制度差・外れ値の注記生成**（前処理で1回・コミット）
     — 江戸川区（制度が別枠）／中央区（本物の供給不足）／島嶼部（母数不足）を**区別**する
- **なぜAIでやる必要があるのか（ルールベースで書けない理由）**：
  1. 局ごとにCSVの様式が違い**毎年変わる**（学童はヘッダ6行目・2ブロック横並び、
     学校一覧は多階層ヘッダ、推計は縦持ち＋和暦列）。**LLMは値に触らずプランだけ作る**ので
     ハルシネーションが数値に混入しない
  2. **数値を作るのは都の公式係数であってLLMではない。** LLMは言葉→係数の写像だけ
  3. 数値ルールでは全部「異常値」としか言えない。
     **江戸川区と中央区の違いは各区の制度を読まないと分からない**
- **精度の担保やフォールバックの方法**：
  - 2はJSONスキーマで検証してから適用。`trend` は `[-0.05,+0.05]`、`units` は `[0,5000]` にクランプ
  - 検証に落ちたら「解釈できませんでした」を返し、**ベースラインのスコアとヒートマップは
    表示され続ける**
  - **クレジット（チーム$100・追加は承認制）対策として、1と3は前処理で1回だけ実行し
    結果をコミット。実行時に呼ぶのは2だけ**
