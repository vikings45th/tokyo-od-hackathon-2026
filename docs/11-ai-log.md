## 作品そのものにAIを組み込んだ場合（あれば）

実装にLLMを使ったなら、ここに**何をどう使ったか**を書いてください。
提出項目③にそのまま転記できます。

**3か所で使います**（詳細は [`docs/14-basic-design.md`](14-basic-design.md) §7）。

- **使ったモデル / サービス**：Cloudflare Workers AI（**Qwen3 30B FP8**・事務局提供）
- **何を処理させているか**：
  1. **様式不定CSVの読解ETL**（前処理で1回・プランをコミットして固定）
     — 先頭30行を渡し「ヘッダ行番号・列対応・ブロック分割・数値クリーニング規則」の
     **JSONプラン**を生成させ、決定論的パーサがそれを実行する
  2. **自然文シナリオ → 都の公式係数へのパラメータ変換**（実行時）
     — 「駅前に600戸のマンションが2028年完成」を、`25es_survey` の
     住宅種別×学年別児童発生率の**どれをどこに幾つ適用するか**に翻訳する
  3. **制度差・外れ値の注記生成**（前処理で1回・コミット）
     — 江戸川区（制度が別枠）／中央区（本物の供給不足）／島嶼部（母数不足）を**区別**する
- **なぜAIでやる必要があるのか（ルールベースで書けない理由）**：
  1. 局ごとにCSVの様式が違い**毎年変わる**（学童はヘッダ6行目・2ブロック横並び、
     学校一覧は多階層ヘッダ、推計は縦持ち＋和暦列）。**LLMは値に触らずプランだけ作る**ので
     ハルシネーションが数値に混入しない
  2. **数値を作るのは都の公式係数であってLLMではない。** LLMは言葉→係数の写像だけ
  3. 数値ルールでは全部「異常値」としか言えない。
     **江戸川区と中央区の違いは各区の制度を読まないと分からない**
- **前処理でやっていること（AIではない部分）**：
  学童3時点 × 公立学校一覧3年分から**登録率トレンドを実測**（+0.84pt/年）。
  推計3ヴィンテージから**予測誤差を実測**（2年先の絶対誤差平均1.51%）。
  **モデルの仮定に数字の裏づけを与えるのが目的です**
- **精度の担保やフォールバックの方法**：
  - 2はJSONスキーマで検証してから適用。`trend` は `[-0.05,+0.05]`、`units` は `[0,5000]` にクランプ
  - 検証に落ちたら「解釈できませんでした」を返し、**ベースラインのスコアとヒートマップは
    表示され続ける**
  - **クレジット（チーム$100・追加は承認制）対策として、1と3は前処理で1回だけ実行し
    結果をコミット。実行時に呼ぶのは2だけ**

## 2026-08-22 ③UI担当 — 生成AIの構成を1か所減らした（記録）

**決定：`/api/scenario`（実行時 Workers AI）を v1 では作らない。**

- 経緯：②が `src/core/` を実装完了（34テスト green）した時点で、FR-7（自然文シナリオ）
  は未着手のまま `PRESET_SCENARIOS` 5件に置き換えられていた。チームで受け入れを決定
- 理由
  1. Workers AI のクレジットは**チーム$100・追加は承認制**。ユーザー操作のたびに呼ぶ
     設計は上限に当たる（`docs/05-tech.md`）
  2. Cloudflareライセンスは**申請から発行まで1週間程度**の見込みで、8/23 の提出に
     間に合わない可能性がある
  3. 「**数値を作るのは都の公式係数であってLLMではない**」という設計の主張は、
     入力が自然文でもボタンでも変わらない。落としても中核が壊れない
- 結果：**サーバーが1つも無い構成**になった。静的ホスティングだけで提出できる
- **提出項目③に書ける生成AIの実装は、①の前処理2用途に集約された**
  （様式不定CSVの読解ETLプラン生成／制度差・外れ値の注記文生成）。
  依頼は `docs/18-request-to-data.md`。**まだ未実装なので、ここが最優先**

## 2026-08-22 ③UI担当 — 開発でのAI活用（提出項目③の材料）

- **Claude Code（Opus）でUI詳細設計とモックを作成。** 素のHTML/CSS/JSで
  スクロール型の画面モックを書き、**Playwright でスクリーンショットを撮って
  実際に目視**してから React へ移植した
  - これで初版のモックから**描画バグを3件検出**した（凡例のハッチが全ポリゴンに
    かかる／ヒートマップのハッチで数字が読めない／ランキングのバーが `<span>` の
    ため `height:100%` が効かず不可視）。**数えるだけでは見つからない類のバグ**
- **配色は目視で決めず検証器にかけた。** `dataviz` スキルの `validate_palette.js` に
  ライト／ダーク両方のランプを通し、コントラスト比で落ちる組み合わせを排除した
  - 実測：ライトの最淡色 `#86b6ef` は `#ffffff`（2.11）と `#fcfcfb`（2.06）では
    2:1 を満たすが、`#f7f7f5`（1.97）と `#f2f2ef`（1.88）では**落ちる**。
    → **セクション背景をグレーにできない**という制約がここで判明した
- **色の5段ビンは実測分布から決めた。** 契約に書いていた `[0,10,25,40,60]` を
  588セル（49自治体×12年度）で数えたところ**上位2色がほぼ使われず地図が単色**になると
  分かり、`[0,3,8,15,30]` に変更した（`docs/17-setup-request.md` §4）
