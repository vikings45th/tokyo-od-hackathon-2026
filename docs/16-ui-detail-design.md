## 1. 調査結果（すべて実測・2026-08-22）

### 1-1. 境界データは存在し、**結合キーまで揃っていました**

**都のカタログに都全域の区市町村境界GeoJSONはありません**
（GeoJSON は35件で、港区・目黒区・品川区の点データが中心）。外部調達になります。

採用：`smartnews-smri/japan-topography`（GitHub）。

| | 実測値 |
|---|---|
| 元ファイル | `data/municipality/topojson/s0010/N03-21_13_210101.json`・**52.3 KB** |
| 中身 | 63ジオメトリ＝**23区 + 26市 + 13町村** |
| 属性 | `N03_001`(都道府県) / `N03_004`(自治体名) / **`N03_007`＝全国地方公共団体コード5桁** |
| 加工済み | 境界を1%に簡素化・飛び地は属性でグループ化 |

🔴 **`N03_007` が決め手です。**
①が作った `data/processed/gakudou_stats_by_municipality.csv` の `muni_code` と同じ5桁コードなので、
**名前の表記ゆれを一切踏まずに結合できます。**

**→ `data/geo/tokyo-49.topo.json` を生成済み**（本コミットに含む）。

```
元63ジオメトリ → 49（23区＋多摩26市。島嶼部・郡部の町村を除外）
使用arc 184 / 全arc 236 → 未使用arcを刈って再インデックス
52.3 KB → 31.3 KB
bbox 経度 139.1361〜139.9187 / 緯度 35.5013〜35.8509（東京都本土）
```

⚠️ **島嶼部を残すと本土が豆粒になります。** 49自治体に絞る理由がここにもあります
（母数不足で比率が壊れるという §4-4 の理由と合わせて二重の根拠）。

### 1-2. ベースマップは要りません

塗るのは49ポリゴンだけで、街路も地名も不要です。**依存の実測値**：

```
maplibre-gl 18.5 MB   /   leaflet 3.6 MB   /   d3-geo 0.2 MB ＋ topojson-client 0.1 MB
```

**ベースマップを使うとタイル配信の外部ホスト依存が生まれ、静的配信の利点を失います**
（審査中にタイル側が落ちるリスクも背負う）。OSM由来タイルは **ODbL** も絡みます。

→ **d3-geo で投影し、SVG の `<path>` を49本描く。**
CSSでホバー・選択・トランジションが素直に書け、HeroUIのテーマ変数もそのまま効きます。

### 1-3. HeroUI は React 19 ＋ Tailwind 4 を強制する

```
@heroui/react 3.2.4  peerDependencies:
  react >=19.0.0 / react-dom >=19.0.0 / tailwindcss >=4.0.0
  react-aria ^3.51.0 / react-aria-components ^1.20.0
```

**CSSだけのライブラリではありません。** ライセンスは全て許容的で、
**コピーレフト（ソース開示義務）はありません**：

```
MIT         react / react-dom / @heroui/react / @heroui/styles / tailwindcss
Apache-2.0  react-aria-components / react-aria / @react-aria/i18n
ISC         d3-geo / topojson-client
```

⚠️ **Apache-2.0 は NOTICE があれば配布物への同梱義務**があります → §8。

### 「ダッシュボードに見える」原因と、その対処

最初のモックはダッシュボードに見えました。**原因は装飾ではなく構造**です。

| 症状 | 原因 | 対処 |
|---|---|---|
| 全部が同時に見える | カードをタイル状に並べていた | **縦に流す。1画面1主張** |
| 主役がない | 13px の文字が均等に散っていた | **96px / 15px / 11px の3段**に落とす |
| 情報が「並んでいる」だけ | **KPIタイル4つの横並び** | **不足人数だけを巨大に1つ**。他は下に1行 |
| Excelに見える | 588セルの格子 | **上位10＋選択中**に絞る（「49自治体すべて」で展開） |
| 管理画面の作法 | 全要素が枠線つきの箱 | **枠線を全廃**。区切りは余白と `border-top` 1本だけ |

### 文字量の方針

```
静的テキスト 478字 → うち 215字（45%）が出典・ライセンス表記
```

🔴 **出典は大会ルールの「絶対に捨てない」提出要件**、
**注記（中央区・江戸川区）は消すと誤情報**になります。

→ **「減らす」ではなく「主役から外す」。**

| 対象 | 処置 |
|---|---|
| 出典・ライセンス | **S5 に専用セクション**を与える。ツール部からは消える |
| 注記の長文 | **1行に要約 ＋ `<details>` で全文**。消さない |
| basis の説明 | **「推定」の2文字＋`title` でホバー全文** |
| 「濃いほど…」「縦＝自治体…」 | **削除**（凡例と軸で自明） |
| ヘッダのサブタイトル | **S0 のヒーローに昇格** |

## 3. 地図の詳細設計

| 項目 | 設計 |
|---|---|
| データ | `data/geo/tokyo-49.topo.json`（**31.3 KB**・生成済み） |
| プロパティ | `{ code: '13102', name: '中央区' }`（`N03_007` / `N03_004` を改名済み） |
| 投影 | `d3.geoMercator().fitSize([w,h], fc)`。東京都だけなので投影の厳密さは不要 |
| 描画 | `topojson.feature(topo, topo.objects.tokyo)` → `d3.geoPath()` → `<path>` 49本 |
| 結合 | 🔴 **`properties.code` ↔ `Muni.code`。名前では結合しない** |
| 塗り | 総合スコアの5段ビン（§5） |
| 枠線 | 1px・`--surface-1`。**塗りの隣接を切る**（`dataviz` のスペーサ規則） |
| ホバー | ツールチップ：自治体名・スコア・需要／供給／不足人数・注記 |
| 選択 | 2px リング。ランキングとヒートマップに連動 |
| データなし | 中立グレー。🔴 **0点と区別する**（`score: null`） |

### 3-2. 拡大縮小・移動【自前実装・依存を増やさない】

```
d3-zoom 85KB ＋ 依存5件   vs   自前（pointer events ＋ viewBox）0KB・約40行
```

**SVG の `viewBox` を書き換えるだけ**なので `<path>` は再生成されません。

| 操作 | 挙動 |
|---|---|
| ホイール | カーソル位置を固定点に拡大縮小（1x〜9x でクランプ） |
| ドラッグ | 平行移動（境界でクランプ） |
| ダブルクリック | 初期表示に復帰 |
| 「23区へ」「全体」 | 23区の bbox にフィット／全体に戻す |

- 線幅は `vector-effect="non-scaling-stroke"` で保つ
- 🔴 **23区が小さい問題がここで実用的に解決します**（面積バイアスの補正はランキングが担当）
- ピンチズームは捨てます（審査は動画・モバイルは「崩れないだけ」）

### 3-3. スクロール演出

**`IntersectionObserver` ＋ CSS のみ。ライブラリを入れません。**

- `.rise` に observer を張り `data-in` を立てて `opacity`／`translateY` で出す
- **S3 の sticky 地図**：340vh の中に3つのステップを置き、
  `rootMargin:'-50% 0px -50% 0px'` で「いまどのステップか」を判定して年度を切り替える
- 🔴 **既定は可視**。`body.js` が付いたときだけ隠す → **JSが落ちても読める**
- 🔴 **`prefers-reduced-motion` でアニメを止める**

```tsx
// src/ui/map/TokyoMap.tsx（骨子）
const fc = useMemo(() => topojson.feature(topo, topo.objects.tokyo), []);
const path = useMemo(() => d3.geoPath(d3.geoMercator().fitSize([W, H], fc)), []);
const byCode = useMemo(() => new Map(cells.map(c => [c.muni, c])), [cells]);
// cells は Heatmap.cells を focusYear で絞ったもの
```

## 5. 色設計

**ライト基調を既定**、ダークも同じ5色で用意します（`?theme=dark` / `data-theme`）。

> 🔴 **2026-08-23 変更：単一色相の濃淡 → 緑・グレー・赤のダイバージング配色に変更しました。**
> 直前までは「赤緑は色覚多様性で最も判別しにくいので使わない」という方針で、
> 単一色相（青）の濃淡で運用していました。
> ③担当の判断でダイバージング（低=緑／中央=グレー／高=赤）へ切り替えています。
>
> **この変更は `dataviz` スキルが挙げる非交渉事項に反する認識で、推奨はしていません。**
> 赤緑は色覚多様性（赤緑色覚異常。CVDの中で最多）で最も判別しにくい組み合わせです。
> 緩和策として、このアプリはセルに数値（`ink`）と凡例テキスト（`BIN_LABELS`）を必ず併記しており、
> 色だけで5段を判別させる場面はありません。それでも色単独での判別は困難なままです。
> 元の単一色相案に戻す場合は git 履歴（本ファイルと `src/ui/palette.ts` の 2026-08-23 以前）を参照してください。

```
ライト（既定・surface #fcfcfb）  低 → 中央 → 高
  #2f9e52 → #8fbb98 → #9a9892 → #d99a8a → #c23b30     緑 → グレー → 赤。中心に向けて彩度を落とす

ダーク（surface #1a1a19）        低 → 中央 → 高
  #35a75f → #5c7d63 → #8a8983 → #b06a5c → #e0574a     同じ配色をダーク輝度帯に再調整
```

`dataviz` の `validate_palette.js` は単色ランプ用の `--ordinal` しか無く、多色のダイバージングには
使えないため、OKLCH輝度帯・彩度・対面コントラストは個別に手計算で確認しました
（詳細は `src/ui/palette.ts` 冒頭のコメント）。ライト帯は全色 L 0.43〜0.77、ダーク帯は全色 L
0.48〜0.67 に収まっています。中央グレーおよびその隣接色は彩度フロア(0.10)を意図的に下回りますが、
これはダイバージング配色の作法（中心に向けて彩度を落とす）であり不備ではありません。

> 🔴 **ライトでは背景をグレーにできません。** 実測：
> ```
> #ffffff 2.11:1 ✅   #fcfcfb 2.06:1 ✅   #f7f7f5 1.97:1 ⛔   #f2f2ef 1.88:1 ⛔
> ```
> 旧・単色ランプの最淡 `#86b6ef` が対面2:1を割ることの記録です。**純白系を使うこと。**
> 結果的にそれが Apple 系のページの作法とも一致します。

### 5-1. 色の5段ビンは `[0, 2, 6, 12, 25]`【2026-08-23 変更】

以前は `[0, 3, 8, 15, 30]` を実測分布（49自治体 × 12年度 ＝ 588セル）に合わせて採用していました：

| bins | 2027年度 | 2031年度 | 2038年度 |
|---|---|---|---|
| `[0,10,25,40,60]`（旧契約） | 38 / 10 / 1 / 0 / 0 | 42 / 6 / 0 / 1 / 0 | 16 / 31 / 1 / 1 / 0 |
| `[0,3,8,15,30]`（2026-08-22 採用） | 17 / 17 / 12 / 3 / 0 | 25 / 13 / 8 / 2 / 1 | 4 / 6 / 19 / 18 / 2 |

実測の裾（`[0,3,8,15,30]` 決定時点）：pooled p50 = 5.5 / p75 = 10.4 / p90 = 15.8 / p99 = 41.5 / max = 50.8。
588セル中 **137 が score 0**（＝完全に足りる）。

> 🔴 **`[0, 2, 6, 12, 25]` への変更は③の指示による直接指定で、588セルでの再測定はしていません。**
> 上の分布表・p50/p75/p90 は古い値のままです。年度が進んでも上位2色（高severity）が
> 使われない／使われすぎるといった偏りが出ていないか、実データで見た目を確認してください。

🔴 **分位ではなく固定値**です。年度やシナリオを変えても色の意味が動きません。
所有は③（`src/ui/palette.ts`）。②が `Heatmap.bins` を削除したのは正しい判断でした。

凡例の文言：`〜2% / 2〜6% / 6〜12% / 12〜25% / 25%〜`（需要のうち受け皿に入れない割合）。

### 5-2. 折れ線の2系列【検証済み】

需要と受け入れ実績は**カテゴリカル2系列**なので、ランプとは別に色を取ります。

```
ライト（surface #fcfcfb）  需要 #1c5cab / 受け入れ実績 #b06a00   → ALL CHECKS PASS
ダーク（surface #101011）  需要 #4a90e2 / 受け入れ実績 #c98410   → ALL CHECKS PASS
```

> ⚠️ ダークは最初 `#9ec5f4` / `#fab219` で試して **Lightness band と Chroma floor が FAIL**
> （どちらも L 0.81 で、ダークの許容帯 0.48〜0.67 の外。青は chroma 0.079 でグレーに読まれる）。
> 検証器の指示どおり差し替えました。**目視で選んでいたら気づけません。**

**軸は1本です（二軸グラフにしない）。** 需要も供給も単位は「人」。
2系列なので**凡例を必ず出し、線の右端に直接ラベルも付けます**（色だけで identity を作らない）。

**セルの文字色はランプの明度と対で持ちます**（`PALETTE.ink[]`）。
テーマを変えると明暗が逆転するので、`score < 25` のような固定条件で分岐しないこと。

**ステータス色は別枠**でスコアのランプに混ぜません。必ず**アイコン＋ラベルと併用**します。

> ⚠️ **色や背景を変えたら必ず検証し直してください。**
> `validate_palette.js` の `--ordinal` は単色ランプ専用で、5-1のダイバージング配色（多色）には
> 使えません。輝度帯・彩度・対面コントラストは個別に手計算で確認する運用です
> （`src/ui/palette.ts` 冒頭のコメントに数値の根拠あり）。

## 6. 不確実性の表現【最重要】

**色は「確実」に見えてしまいます。** 家の購入判断に使わせる以上、ここを手当てしないと
「誠実な予測」という主張そのものが崩れます。

| 対象 | 表現 |
|---|---|
| `basis: 'bridged'`（2032年度以降＝都の推計を接続した推定） | **45°の斜線テクスチャを重ねる。** 凡例に「都の公式推計／接続推定」と明記。ヒートマップは境界に縦罫 |
| 予測区間 | 詳細チャートで**帯（塗り）**として描く。🔴 **中心線だけを描かない** |
| 3年先以上（誤差を実測していない区間） | 帯を広げ、**「1年先・2年先しか誤差を実測していない」と注記** |
| スコアの精度 | 🔴 **連続グラデにせず5段ビン。** 細かい階調は精度を主張しすぎる |

> **テクスチャは `dataviz` が用意している正式なアクセシビリティ・チャネル**です
> （45° とその 135° ミラー）。ここでは「確からしさが違う」の表現に転用します。

**実測できる誤差は1年先と2年先だけ**です（推計ヴィンテージが令和5・6・7の3世代のため）。

```
1年先：平均 +0.25% / 絶対誤差平均 0.93% / p10 -1.46% / p90 +1.57%
2年先：平均 +0.26% / 絶対誤差平均 1.51% / p10 -2.13% / p90 +2.61%
```

## 7. HeroUI の責務境界

| HeroUI を使う | 自前で書く（SVG＋CSS変数） |
|---|---|
| Select / Slider / Input / Card / Tabs / Tooltipの器 / Modal / Toast / Skeleton / テーマ切替 | **地図・ヒートマップ・ランキング棒・折れ線・予測区間の帯** |

**データ可視化は HeroUI の守備範囲外**です。最初に線を引いておくと迷いません。
可視化は HeroUI のテーマトークンから CSS 変数で色を受け取ります。

## 7-2. 可視化ライブラリは入れない【実測で判断】

**チャートライブラリは採用しません。** 主役2つがその守備範囲外だからです。

| | unpacked | deps | ライセンス | 用途 |
|---|---|---|---|---|
| **`d3-geo`** | 222 KB | 1 | ISC | **必須**：地図の投影 |
| **`topojson-client`** | 66 KB | 1 | ISC | **必須**：TopoJSON の展開 |
| `d3-scale` | 170 KB | 5 | ISC | あると楽：スコア→色ビン、年度→X座標 |
| `d3-shape` | 241 KB | 1 | ISC | あると楽：折れ線と予測区間の帯 |
| ~~recharts~~ | **7.1 MB** | 11 | MIT | 不採用 |
| ~~victory~~ | 2.2 MB | **27** | MIT | 不採用 |
| ~~@observablehq/plot~~ | 1.5 MB | 3 | ISC | 不採用 |
| ~~@nivo/core~~ | 248 KB | **14** | MIT | 不採用 |

**理由**：

- **地図は `d3-geo`、ヒートマップは `<rect>` を588個並べるだけ、ランキングは横棒10本。**
  チャートライブラリが役に立つのは**折れ線1系列だけ**で、そのために
  Reactコンポーネント階層を持ち込むのは割に合いません
- `dataviz` が求める制御（5段ビン・`bridged` の斜線テクスチャ・`null` の別扱い・
  予測区間の帯）は、**ライブラリのAPIと戦うことになります**。自前SVGなら素直に書けます

> 💡 **必須は `d3-geo` と `topojson-client` の2つだけ**です。
> 5段ビンは閾値関数3行、帯は `path` の `M/L` で10行程度なので、
> `d3-scale` / `d3-shape` は「あると楽」に留まります。
> **②のセットアップを軽くしたいなら2つだけでも成立します。**
>
> ⚠️ `d3-array` は `d3-scale` の依存で入るので、明示的な追加は不要です。
> unpacked サイズは実バンドルではありません（tree-shaking が効く）。
> **②はビルド後に実測してください。**

## 8. ファイル所有と衝突回避

```
src/
  types.ts          ★②所有。③は読むだけ。変更したいときは②に声をかける
  core/  api/       ②のみ
  ui/               ③のみ
    App.tsx  main.tsx
    map/  heatmap/  ranking/  detail/  scenario/
    styles.css      ← Tailwind のエントリ。③所有
    theme.ts        ← HeroUI テーマ設定。③所有
data/geo/           ③（本コミットで生成済み）
```

**衝突するのはフレームワークではなく、次の3ファイルだけです。**

| ファイル | 所有 | 扱い |
|---|---|---|
| `package.json` / `package-lock.json` | **②** | **②が最初に1回だけセットアップ。以降③は触らない** |
| `vite.config.ts` | **②** | Tailwind 4 の Vite プラグイン追加も**②が1回だけ** |
| `index.html` | **②** | React のルート要素まで②が用意。以降③は触らない |

→ **②が「1回のセットアップ」を済ませた時点で分岐**すれば、以後の衝突はゼロです。
`docs/10-roles-schedule.md` の「契約先行」と同じ考え方です。

**ライセンス表記**：ビルド時に `LICENSES.txt` を生成して `dist/` に含めます
（Apache-2.0 の NOTICE 対応）。**画面に出す出典表記とは別物**なので混同しないこと。

## 8-2. 入力の仕様（早生まれ）

**生まれ年だけでは1〜3月生まれが1年ずれます。** 学校教育法では
**4月2日〜翌年4月1日生まれが同学年**です。

```
入学年度 = 生まれ年 + (生まれ月 >= 4 ? 7 : 6)
  2024年4月 → 2031年度 ／ 2025年3月 → 2031年度 ／ 2025年4月 → 2032年度
```

→ **年と月の2つを選ばせます**（`entryYearOf(year, month)`）。
未出生なら予定月で構いません。**購入判断に使わせる以上、1年のずれは許容できません。**

## 11. アクセシビリティ

- **色だけに依存しない**：ランキングの数値・ヒートマップのセル値・凡例・テクスチャ
- SVG の各 `<path>` に `role="img"` と `aria-label`（例「中央区 リスク41」）
- **キーボードで自治体を選べる**（react-aria が下地を持つ＝HeroUI採用の実利）
- **表形式ビューを用意**（`dataviz` の非交渉事項。コントラストWARNの救済でもある）
- dark モードは**自動反転ではなく専用ステップを検証済み**（§5）
