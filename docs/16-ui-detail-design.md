## 1. 調査結果（すべて実測・2026-08-22）

### 1-1. 境界データは存在し、**結合キーまで揃っていました**

**都のカタログに都全域の区市町村境界GeoJSONはありません**
（GeoJSON は35件で、港区・目黒区・品川区の点データが中心）。外部調達になります。

採用：`smartnews-smri/japan-topography`（GitHub）。

| | 実測値 |
|---|---|
| 元ファイル | `data/municipality/topojson/s0010/N03-21_13_210101.json`・**52.3 KB** |
| 中身 | 63ジオメトリ＝**23区 + 26市 + 13町村** |
| 属性 | `N03_001`(都道府県) / `N03_004`(自治体名) / **`N03_007`＝全国地方公共団体コード5桁** |
| 加工済み | 境界を1%に簡素化・飛び地は属性でグループ化 |

🔴 **`N03_007` が決め手です。**
①が作った `data/processed/gakudou_stats_by_municipality.csv` の `muni_code` と同じ5桁コードなので、
**名前の表記ゆれを一切踏まずに結合できます。**

**→ `data/geo/tokyo-49.topo.json` を生成済み**（本コミットに含む）。

```
元63ジオメトリ → 49（23区＋多摩26市。島嶼部・郡部の町村を除外）
使用arc 184 / 全arc 236 → 未使用arcを刈って再インデックス
52.3 KB → 31.3 KB
bbox 経度 139.1361〜139.9187 / 緯度 35.5013〜35.8509（東京都本土）
```

⚠️ **島嶼部を残すと本土が豆粒になります。** 49自治体に絞る理由がここにもあります
（母数不足で比率が壊れるという §4-4 の理由と合わせて二重の根拠）。

### 1-2. ベースマップは要りません

塗るのは49ポリゴンだけで、街路も地名も不要です。**依存の実測値**：

```
maplibre-gl 18.5 MB   /   leaflet 3.6 MB   /   d3-geo 0.2 MB ＋ topojson-client 0.1 MB
```

**ベースマップを使うとタイル配信の外部ホスト依存が生まれ、静的配信の利点を失います**
（審査中にタイル側が落ちるリスクも背負う）。OSM由来タイルは **ODbL** も絡みます。

→ **d3-geo で投影し、SVG の `<path>` を49本描く。**
CSSでホバー・選択・トランジションが素直に書け、HeroUIのテーマ変数もそのまま効きます。

### 1-3. HeroUI は React 19 ＋ Tailwind 4 を強制する

```
@heroui/react 3.2.4  peerDependencies:
  react >=19.0.0 / react-dom >=19.0.0 / tailwindcss >=4.0.0
  react-aria ^3.51.0 / react-aria-components ^1.20.0
```

**CSSだけのライブラリではありません。** ライセンスは全て許容的で、
**コピーレフト（ソース開示義務）はありません**：

```
MIT         react / react-dom / @heroui/react / @heroui/styles / tailwindcss
Apache-2.0  react-aria-components / react-aria / @react-aria/i18n
ISC         d3-geo / topojson-client
```

⚠️ **Apache-2.0 は NOTICE があれば配布物への同梱義務**があります → §8。

## 3. 地図の詳細設計

| 項目 | 設計 |
|---|---|
| データ | `data/geo/tokyo-49.topo.json`（**31.3 KB**・生成済み） |
| プロパティ | `{ code: '13102', name: '中央区' }`（`N03_007` / `N03_004` を改名済み） |
| 投影 | `d3.geoMercator().fitSize([w,h], fc)`。東京都だけなので投影の厳密さは不要 |
| 描画 | `topojson.feature(topo, topo.objects.tokyo)` → `d3.geoPath()` → `<path>` 49本 |
| 結合 | 🔴 **`properties.code` ↔ `Muni.code`。名前では結合しない** |
| 塗り | 総合スコアの5段ビン（§5） |
| 枠線 | 1px・`--surface-1`。**塗りの隣接を切る**（`dataviz` のスペーサ規則） |
| ホバー | ツールチップ：自治体名・スコア・需要／供給／不足人数・注記 |
| 選択 | 2px リング。ランキングとヒートマップに連動 |
| データなし | 中立グレー＋斜線。🔴 **0点と区別する**（`score: null`） |

```tsx
// src/ui/map/TokyoMap.tsx（骨子）
const fc = useMemo(() => topojson.feature(topo, topo.objects.tokyo), []);
const path = useMemo(() => d3.geoPath(d3.geoMercator().fitSize([W, H], fc)), []);
const byCode = useMemo(() => new Map(cells.map(c => [c.muni, c])), [cells]);
// cells は Heatmap.cells を focusYear で絞ったもの
```

## 5. 色設計【検証済み・目視で決めていない】

`dataviz` スキルの検証器で **light / dark 両モードとも全項目PASS**。

```
スコアの5段ビン（sequential・単一色相の青）
  light : #86b6ef → #5598e7 → #2a78d6 → #1c5cab → #0d366b
  dark  : #cde2fb → #9ec5f4 → #6da7ec → #2a78d6 → #184f95
```

```bash
node <dataviz>/scripts/validate_palette.js \
  "#86b6ef,#5598e7,#2a78d6,#1c5cab,#0d366b" --mode light --ordinal
# → ALL CHECKS PASS（Lightness monotone / Adjacent ΔL / Light-end contrast 2.06:1 / Single hue）
node <dataviz>/scripts/validate_palette.js \
  "#cde2fb,#9ec5f4,#6da7ec,#2a78d6,#184f95" --mode dark --ordinal
# → ALL CHECKS PASS（Light-end contrast 2.15:1）
```

**なぜ赤緑にしないか**：色覚多様性で最も落ちる組み合わせだからです。
**連続量は単一色相の濃淡が正解**（`dataviz` の非交渉事項）。

**なぜ最淡を `#86b6ef` で止めるか**：コロプレスの規則では最淡が面に沈むのは許容ですが、
**23区のポリゴンは小さく、沈むと「スコア0」と「データなし」が区別できなくなる**ため、
ordinal の下限（対面2:1）を守ります。

**ステータス色は別枠**で、スコアのランプには混ぜません。

```
good #0ca30c / warning #fab219 / serious #ec835a / critical #d03b3b
```

待機児童のバッジなどにのみ使い、**必ずアイコン＋ラベルと併用**します
（色だけで意味を持たせない）。

> ⚠️ **色を変えたら必ず検証器にかけ直してください。** 目視でCVD安全性は判断できません。

## 6. 不確実性の表現【最重要】

**色は「確実」に見えてしまいます。** 家の購入判断に使わせる以上、ここを手当てしないと
「誠実な予測」という主張そのものが崩れます。

| 対象 | 表現 |
|---|---|
| `basis: 'bridged'`（2032年度以降＝都の推計を接続した推定） | **45°の斜線テクスチャを重ねる。** 凡例に「都の公式推計／接続推定」と明記。ヒートマップは境界に縦罫 |
| 予測区間 | 詳細チャートで**帯（塗り）**として描く。🔴 **中心線だけを描かない** |
| 3年先以上（誤差を実測していない区間） | 帯を広げ、**「1年先・2年先しか誤差を実測していない」と注記** |
| スコアの精度 | 🔴 **連続グラデにせず5段ビン。** 細かい階調は精度を主張しすぎる |

> **テクスチャは `dataviz` が用意している正式なアクセシビリティ・チャネル**です
> （45° とその 135° ミラー）。ここでは「確からしさが違う」の表現に転用します。

**実測できる誤差は1年先と2年先だけ**です（推計ヴィンテージが令和5・6・7の3世代のため）。

```
1年先：平均 +0.25% / 絶対誤差平均 0.93% / p10 -1.46% / p90 +1.57%
2年先：平均 +0.26% / 絶対誤差平均 1.51% / p10 -2.13% / p90 +2.61%
```

## 7-2. 可視化ライブラリは入れない【実測で判断】

**チャートライブラリは採用しません。** 主役2つがその守備範囲外だからです。

| | unpacked | deps | ライセンス | 用途 |
|---|---|---|---|---|
| **`d3-geo`** | 222 KB | 1 | ISC | **必須**：地図の投影 |
| **`topojson-client`** | 66 KB | 1 | ISC | **必須**：TopoJSON の展開 |
| `d3-scale` | 170 KB | 5 | ISC | あると楽：スコア→色ビン、年度→X座標 |
| `d3-shape` | 241 KB | 1 | ISC | あると楽：折れ線と予測区間の帯 |
| ~~recharts~~ | **7.1 MB** | 11 | MIT | 不採用 |
| ~~victory~~ | 2.2 MB | **27** | MIT | 不採用 |
| ~~@observablehq/plot~~ | 1.5 MB | 3 | ISC | 不採用 |
| ~~@nivo/core~~ | 248 KB | **14** | MIT | 不採用 |

**理由**：

- **地図は `d3-geo`、ヒートマップは `<rect>` を588個並べるだけ、ランキングは横棒10本。**
  チャートライブラリが役に立つのは**折れ線1系列だけ**で、そのために
  Reactコンポーネント階層を持ち込むのは割に合いません
- `dataviz` が求める制御（5段ビン・`bridged` の斜線テクスチャ・`null` の別扱い・
  予測区間の帯）は、**ライブラリのAPIと戦うことになります**。自前SVGなら素直に書けます

> 💡 **必須は `d3-geo` と `topojson-client` の2つだけ**です。
> 5段ビンは閾値関数3行、帯は `path` の `M/L` で10行程度なので、
> `d3-scale` / `d3-shape` は「あると楽」に留まります。
> **②のセットアップを軽くしたいなら2つだけでも成立します。**
>
> ⚠️ `d3-array` は `d3-scale` の依存で入るので、明示的な追加は不要です。
> unpacked サイズは実バンドルではありません（tree-shaking が効く）。
> **②はビルド後に実測してください。**

## 8-2. 入力の仕様（早生まれ）

**生まれ年だけでは1〜3月生まれが1年ずれます。** 学校教育法では
**4月2日〜翌年4月1日生まれが同学年**です。

```
入学年度 = 生まれ年 + (生まれ月 >= 4 ? 7 : 6)
  2024年4月 → 2031年度 ／ 2025年3月 → 2031年度 ／ 2025年4月 → 2032年度
```

→ **年と月の2つを選ばせます**（`entryYearOf(year, month)`）。
未出生なら予定月で構いません。**購入判断に使わせる以上、1年のずれは許容できません。**

## 10. パフォーマンス

🔴 **trend スライダーのドラッグが最大のリスク**です。
1目盛り動かすたびに **49自治体 × 12年度 × 予測エンジン** が走ります。

- スライダーは即時再計算せず **`requestAnimationFrame` で間引く**
- 重い場合は**②にメモ化を依頼**（`src/core/` は②の担当）
- 地図の49パスは `React.memo` ＋ `key={code}` で再生成を防ぐ
- **まず計測してから最適化する。** 49ポリゴンは本来軽いはずです

## 11. アクセシビリティ

- **色だけに依存しない**：ランキングの数値・ヒートマップのセル値・凡例・テクスチャ
- SVG の各 `<path>` に `role="img"` と `aria-label`（例「中央区 リスク41」）
- **キーボードで自治体を選べる**（react-aria が下地を持つ＝HeroUI採用の実利）
- **表形式ビューを用意**（`dataviz` の非交渉事項。コントラストWARNの救済でもある）
- dark モードは**自動反転ではなく専用ステップを検証済み**（§5）

## 12. 異常時の振る舞い

| 事象 | 振る舞い |
|---|---|
