> テーマ確定後に、この方針を具体化してください。

## 前提

### なぜ Cloudflare か

事務局が参加チーム向けに**サービス公開環境（Cloudflare Paidプラン相当）**と
**Cloudflare Workers AI**（OpenCode経由）を提供しています。

- 公開環境が用意されている＝**デプロイ先で悩む必要がない**
- Final Stage 進出後の実装支援まで見据えると、事務局提供環境に乗るのが素直
- Workers / Pages はフロント＋軽量APIの構成に向いている

**特別な理由がなければ Cloudflare Workers / Pages を使ってください。**

### 1.5日で作るという制約

技術選定の判断基準は**「8/23に動くか」の一点**です。

- 慣れていない技術を新しく学ぶ余裕はありません
- 3人が全員触れる技術を選んでください
- 凝った構成より、**確実に動く単純な構成**

## 推奨構成

```
[ブラウザ]
    ↓
[Cloudflare Pages]  … 静的フロントエンド
    ↓ (必要なら)
[Cloudflare Workers] … APIプロキシ／集計／AI呼び出し
    ↓
[東京都オープンデータ] … カタログサイト or APIカタログ
```

**データの取り方は2択：**

| 方式 | いつ使うか | 注意点 |
|---|---|---|
| **事前取得してリポジトリに同梱** | データが更新されない／件数が多い／整形が重い | `data/` に置いてコミット。**まずこちらを検討** |
| **実行時にクライアントから取得** | データが更新される／リアルタイム性が要る | **CORS に注意**。ダメなら Workers 経由でプロキシ |

> ⚠️ **ビルド時にデータを取りに行く構成は避けてください。**
> ネットワークポリシー設定前の環境ではビルドが通らなくなります。

重い前処理はローカルで済ませて結果をコミットするのが確実です。
ブラウザで重い集計をさせない。

## 「技術力」は審査基準です

審査基準の1項目であり、**技術賞という賞そのもの**です（`docs/01-event.md`）。
原文はこうです。

> 技術難易度が高い、技術要素(アーキテクチャやAI等)に合理性がある等、
> **技術力が確かで完成度も高い**サービスであるか

読み取れること：

- **「技術難易度」だけでなく「合理性」と「完成度」が並記されている。**
  凝ったことをするより、**選択に理由があって、ちゃんと動く**方が評価される
- **AI が例示されている。** 事務局が OpenCode / Cloudflare Workers AI を
  提供していることと合わせて、**生成AIの活用は期待されている**と読める
- 提出フォームのエントリー項目③に
  **「技術選定の理由」「生成AI等の活用方法」**の記入欄があります。
  つまり**技術選定を言語化できることまで含めて審査対象**です

→ 技術を選ぶときは「なぜそれを選んだか」を1行で言えるようにしておいてください。
そのまま提出フォームに書けます。

## 技術選定【確定・2026-08-22】

> テーマ確定（候補4「小1の壁」）に伴い確定しました。
> 根拠は [`docs/14-basic-design.md`](14-basic-design.md) §11。
> **この表はそのまま提出フォームのエントリー項目③「技術選定の理由」に転記できます。**

| 項目 | 選択 | 理由（1行で言えること） |
|---|---|---|
| 前処理 | **Python 3.11・標準ライブラリのみ**（`csv`/`json`/`urllib`） | 環境に導入済み。**pandas を入れない**＝3人の環境差でパイプラインが壊れない |
| フロントエンド | **素の TypeScript ＋ Vite** | 3人全員が触れる。React等を新規学習する余裕がない。型が `src/types.ts` の契約に効く |
| スタイリング | **素のCSS（カスタムプロパティ）** | Tailwindの設定に時間を使わない |
| 可視化ライブラリ | **使わない（自前インラインSVG）** | 描くのはヒートマップ＋折れ線＋予測区間の帯だけ。ライブラリを入れるより速い。**書く前に `dataviz` スキルを読む** |
| 地図ライブラリ | **使わない** | 国土地理院ジオコーディングAPIが CONNECT 403。自治体単位のMVPに地図は不要 |
| データ配信 | **静的JSON（`data/app/`）** | **実測455KB / gzip約150KB**。APIもDBも不要だと**測定で言える** |
| 予測計算 | **ブラウザ内（`src/core/`）** | データが小さくサーバー往復が無駄。**「都の推計モデルをブラウザで再実行」が技術的見せ場** |
| バックエンド | **Cloudflare Pages Functions 1本**（`/api/scenario`） | 生成AIの呼び出しだけ。APIキーをブラウザに出さないための最小構成 |
| 生成AI | **Workers AI / Qwen3 30B FP8** | 事務局提供・推奨既定モデル。**$100制約**のため実行時呼び出しは1か所に絞る |
| DB / KV / R2 | **使わない** | 状態を持たない。**特典が間に合わなくても無料プランで動く**ため |
| デプロイ先 | Cloudflare Pages / Workers | 事務局提供環境。**⚠️ 発行待ちのリスクあり（下記）** |

**使わなかった技術に理由があること**は、審査文言
「技術要素（アーキテクチャやAI等）に**合理性がある**」に直接効きます。

```jsonc
// package.json（②がオーナー）
"scripts": {
  "dev":    "vite",
  "build":  "vite build",                 // ⚠️ ネットに行かない。data/ を読むだけ
  "deploy": "wrangler pages deploy dist"  // ローカルマシンから実行
}
```

> ⚠️ **`npm run build` がネットワークに触れないこと**が絶対条件です。
> 3人のうち1人だけビルドできない事故を防ぎます。

> 🔴 **Cloudflare特典が間に合わない場合の代替を決めておくこと。**
> 事務局 Slack によると**ライセンスが2回上限に達し、申請から発行まで
> 1週間程度かかる見込み**です。8/23 に間に合わない可能性があります。
>
> 特典が使えなくても、**Cloudflare の無料プランでも Pages / Workers は使えます**
> （R2・D1 など一部に制限あり）。`data/` に前処理済みデータを置く構成なら
> **静的ホスティングで足りるので、無料プランでも成立します。**
> 提出物は「公開URLで動くこと」なので、特典待ちで止まらないようにしてください。

### 選定の目安

- **フロント**：3人が触れるもの。素の HTML/JS でも問題ない。
  凝ったフレームワークを新規学習する余裕は無い
- **可視化**：Chart.js、D3、Observable Plot など。
  **チャートを作る前に `dataviz` スキルを読むこと**
- **生成AI**：事務局提供の **Cloudflare Workers AI**（OpenCode 経由）。
  使えるモデルは **Qwen3 30B FP8**（推奨既定）／**Qwen2.5 Coder 32B**（入力コスト高）／
  **GPT-OSS 20B**（コンテキスト128K）。
  提出フォームの「生成AI等の活用方法」欄に直結するので、使うなら使い方を記録しておく
  - ⚠️ **クレジットはチームあたり $100**（追加は事務局の承認制）。
    **LLMをユーザー操作のたびに呼ぶ設計は上限に当たります。**
    前処理でLLMを走らせて結果をコミットしておく方が安全です
  - ⚠️ 事務局ルールで **APIキーとシークレットは Secrets Store か環境変数で管理**。
    ソースにハードコードしないこと
  - ⚠️ 提供は **2026年9月まで**。終了後はアクセスを失うので GitHub にバックアップする
  - 出典：https://odh-tokyo2026.code4japan.org/ （公式ガイドブック）
- **地図**：MapLibre GL JS、Leaflet。東京都のデータは地理情報が多い
- **CSS**：素のCSSかTailwind。デザインに時間をかけすぎない

## ディレクトリ構成（案）

**コンフリクト対策として、担当ごとにディレクトリを分けます**
（`docs/07-team-workflow.md`）。

**割り当ての正は [`docs/10-roles-schedule.md`](10-roles-schedule.md) の表です。**
ここはその構成をディレクトリとして書き下したものです。

```
src/
  index.html          エントリポイント
  types.ts            アプリが扱うデータの型（3人で合意。勝手に変えない）
  core/               担当：② ロジック（判定・集計）
  api/                担当：② Workers・LLM呼び出し
  ui/                 担当：③ 画面・入力・結果表示・出典表記
  shared/             共通ユーティリティ（変更前に一声かける）
scripts/              担当：① データ取得・整形
data/
  sample.json         型に沿ったダミーデータ（②③はこれで先に書く）
  *.json / *.csv      取得済みオープンデータ（担当：①）
  SOURCES.md          出典・ライセンス・取得日の記録（担当：①）
docs/                 このディレクトリ
```

`data/SOURCES.md` は**必ず作ってください。** 提出フォームのエントリー項目⑤で
**オープンデータ最大10件の記入が必須**です（`docs/01-event.md`）。
後からまとめようとすると必ず漏れます。

## 開発コマンド

```bash
# 依存インストール
npm install

# ローカル開発サーバ
npx wrangler dev

# デプロイ（ローカルマシンから実行すること）
npx wrangler deploy
```

`.claude/settings.json` で `npx wrangler dev` は許可済み、
`npx wrangler deploy` は確認を挟む設定にしてあります。

## この環境の制約

### デプロイはローカルから

`wrangler login` はブラウザOAuthなのでクラウドセッション内では完結しません。
**デプロイは各自のローカルマシンから。** 詳細は `docs/07-team-workflow.md`。

### ネットワーク制限

ネットワークポリシーを Custom にするまで、クラウドセッションから
東京都のデータも Cloudflare API も触れません。
手順は `docs/07-team-workflow.md`。

## やらないこと

時間がありません。以下は**意識的に捨ててください。**

- ユーザー認証・ログイン機能（デモに不要）
- データベース（静的ファイルとKVで足りるはず）
- テストの網羅（重要な処理だけ）
- レスポンシブの作り込み（審査は動画。想定画面幅を1つ決めて集中する）
- 細かいデザイン調整（伝わればいい）

**削った分を、狙う賞の審査基準に注ぎ込んでください**（`docs/04-ideas.md`）。
「データ活用」を狙うならデータの選定と組み合わせに、
「ソーシャルインパクト」を狙うなら効果の定量化に時間を使う、という配分です。
