## 1. 背景と課題

### 1-1. チームが置いた3仮説（原文）

**課題仮説**

> 東京都内（または都外・海外から東京への移住）を検討する正社員×正社員のデュアルインカム
> 夫婦は、第一子の小学校入学（いわゆる「小1の壁」）を見据えて初めての持ち家購入エリアを
> 検討する際、区・自治体ごとに学童保育の定員・待機児童リスクが大きく異なるにもかかわらず、
> 住宅購入検討の時点でその具体的なリスクを把握できていない。結果として、希望エリアで
> 学童に申し込む前に倍率の高さを知って断念する、あるいは抽選に落ちて対応に困る、
> といった事態が起きている。
>
> **実体験**：杉並区で、申込前から倍率の高さを知って学童への申込・入居を断念した実例あり。
>
> **反証可能なポイント**：エリアごとの学童受け入れ枠・倍率の情報が、既存の手段
> （自治体公開情報、不動産業者、口コミ等）で実際には十分に得られている、と分かれば
> この課題仮説は否定される。

**顧客セグメント仮説**

> 正社員×正社員のデュアルインカムでフルタイム勤務の夫婦。世帯収入は中間層〜上位まで
> 幅広い層を対象とする。現在の居住地は東京都内・都外（地方・海外含む）を問わない。
> 第一子・初めての持ち家購入を検討しており、子の年齢そのものではなく
> **「将来子供が小1になるタイミング」**を見据えて行動する。住宅購入検討を始める時点で
> 「学童の抽選リスクがある」という一般論は既に知っているが、区ごとの具体的なリスクの
> 高低を判断できる情報は持っていない。

**ソリューション仮説**

> 学童クラブ実施状況データ（区・市町村別の登録児童数・待機児童数等）を集計・可視化し、
> 区単位の学童受け入れリスクでエリアをランキングし、おすすめの住宅購入エリアを提案する
> サービス。MVPでは学童リスク単独でランキングするが、将来的に通勤時間・住宅価格帯・
> 学区評価等の他要素と組み合わせられる拡張性を持たせる。

### 1-2. 実測による検証結果

**2026-08-22 に全データを実際にダウンロードして確認しました。以下はすべて実測値です。**

#### ⛔ 検証1：待機児童数ではランキングできない

`学童クラブ事業の区市町村別実施状況`を集計した結果（**2025-05-01 時点**）：

```
待機児童数 = 0 の自治体：48中18（38%）      ※2023-05 時点では 48中17
待機児童数 > 0 の上位（登録児童数に対する比）：
  杉並区481人(7.1%) / 中央区275人(17.6%) / 目黒区246人(8.8%)
  葛飾区227人(4.3%) / 立川市219人(10.4%) / 足立区179人(3.2%)   （都計 3,360人）
```

**絶対数と比率で順位が全く変わります。** 杉並区は絶対数1位ですが比率では7.1%、
**中央区は絶対数4位でも比率17.6%で都内最大**です。

**4割近くが同率1位になります。エリアを並べられません。**
しかも**世田谷区が「待機0＝安全」と表示されます**（登録児童数9,577人という都内最大級の
規模を抱えているのに、です）。0なのは需要が無いからではなく、定義・運用の違いです。

**さらに構造的な欠陥があります。**

> **杉並区の待機児童数は257人。しかし「申込前に断念した人」はカウントされません。**
>
> **課題仮説の実体験そのもの（＝申込を断念した）が、待機児童数という指標には
> 構造的に現れません。** この指標を主軸に据えると、
> **本サービスが助けようとしている当事者を検出できない**という自己矛盾が起きます。

#### ✅ 検証2：主指標は「登録率」にすれば成立する

`顕在需要率 =（登録児童数 + 待機児童数）÷ 公立小学校児童数`（**2025-05・実測**）：

```
対象48自治体の計：143,122 / 558,686 = 0.256
上位：渋谷区0.488 千代田区0.398 板橋区0.345 あきる野市0.327 国分寺市0.319
下位：中央区0.163 品川区0.193 足立区0.194 大田区0.201 中野区0.208
```

> 🔴 **2026-08-22 訂正**：児童数の分母は「公立学校一覧」ではなく**教育人口等推計の総数**を使います。
> 東京都には「小学校」とは別に「義務教育学校」（前期課程＝小1〜6相当を含む9年制校）があり、
> 学校名簿（公立学校一覧）はこれを含みません。義務教育学校の児童も学童を必要とする対象なので、
> **含む値（教育人口等推計）を正としました**（品川区など4自治体で最大20%児童数が変わる）。
> 上位・下位リストもこの基準で再計算済みです。

**0.163〜0.398 に連続分布し、判別力があります。**
意味も直感的です（「その区で、学童を実際に使えている子の割合」）。
**待機児童数は主指標ではなく補助指標**（現在の逼迫のシグナル）として併用します。

#### ⛔ 検証3：課題仮説とソリューション仮説の間にズレがある

課題仮説は「**将来子供が小1になるタイミング**を見据えて行動する」と明記していますが、
ソリューション仮説は「**現在の**登録児童数・待機児童数でランキング」です。

```
2026年  0〜2歳の子がいる。家を買う      ← 意思決定はここ
              ↓ 最大6年
2032年  子が小1。学童に入れない          ← 痛みはここ
```

**現在値のランキングでは課題仮説を満たせません。予測が必須です。**

#### ✅ 検証4：反証可能なポイントへの回答

> 反証条件：受け入れ枠・倍率の情報が、既存の手段で実際には十分得られている

**仮説は否定されません。ただし言い方を正確にする必要があります。**
「情報が無い」のではなく「**比較・将来予測できる形になっていない**」です。

| 実測した事実 | 意味 |
|---|---|
| 生データは東京都オープンデータカタログで**公開されている**（CC BY） | 「入手できない」は誤り。**ここは正直に認める** |
| CSVは**ヘッダが6行目、区部と市町村部が横に並んだ2ブロック構成**、数値は `"1,261 "` 形式 | **そのままでは読めない。**購入検討者が扱える形ではない |
| カタログ上は**令和5年5月1日の1時点のみ** | **トレンドが取れない。将来も見えない** |
| **48%が待機0** | **区の比較ができない**（検証1） |
| **江戸川区は制度が別枠** | **単純比較すると誤情報になる** |
| 将来値が**どこにも無い** | **課題仮説が求める「6年後」に答えられない** |

> ⚠️ **提出フォームには「行政がデータを出していない」と書かないこと。**
> 事実に反しますし、行政審査員3人がいる審査構成で不利です。
> 「**データは公開されているが、比較可能な形に整えられておらず、将来の見通しも存在しない。
> そこを埋める**」と書きます。

#### ✅ 検証5：データ実現性（チーム仮説からの訂正2点）

**訂正1：最新は令和5年5月1日版です**（チームが確認した令和3年度版より新しい）。

**訂正2：「学区単位への拡張は別データソースが必要」は不正確です。**

| | 粒度 | 実測 |
|---|---|---|
| **受け入れ枠**（クラブ数・登録・待機） | **区単位のみ** | 仮説のとおり。**MVPを区単位にする判断は正しい** |
| **需要の母数**（児童数） | **学校単位で取れる** | `公立学校統計調査報告書【東京都公立学校一覧】`（教育庁・CC BY）に**公立小1,255校 × 学年別児童数 ＋ 住所**。令和5・6・7の3年分が同一スキーマ・同一キー（`学校番号`） |

**同じカタログ内に、追加の許諾もなく存在します。**
拡張の道は「別データソースを探す」ではなく「**すでに手元にある**」。

#### ✅ 検証5b：学童データは3時点に拡張済み。**トレンドを実測できました**

チームの①担当が、カタログ掲載分（2023-05）に加えて**福祉局サイトの2025-05・2025-10版**を
取得・整形しました（`data/processed/gakudou_stats_by_municipality.csv`・
62区市町村 × 3時点・全国地方公共団体コードつき）。

これで**当初の限界が2つ消えました。**

| 当初の限界 | 現状 |
|---|---|
| 「登録率のトレンドが都のデータに存在しない」 | ✅ **実測できました。都計 +0.81pt/年**（48自治体・2023-05→2025-05） |
| 「学童は令和5年、推計は令和7年度起点で基準年がずれる」 | ✅ **解消。** 学童 2025-05-01 と教育人口等推計 令和7年度（2025-05-01）が一致 |

```
顕在需要率 =（登録+待機）÷ 児童数（教育人口等推計の総数。義務教育学校の前期課程を含む）
  2023-05：135,143 / 563,282 = 0.2399
  2025-05：143,122 / 558,686 = 0.2562   → +0.81pt/年（48自治体中45が上昇）
```

🔴 **「児童数は減るのに需要は増える」が実証されました。**
児童数は2年で **-0.82%** なのに、登録+待機は **+5.9%** です。

⚠️ **江戸川区はトレンド計算から除外します。** 2023-05 の 4クラブ/141人 から
2025-05 の 72クラブ/6,623人 へと計上方法が変わっており、
そのまま入れると +20pt/年 という断絶由来の値になります
（**スコア計算には含めます**。2025年基準なら顕在需要率0.212で48自治体中9番目に低く、
他自治体と比較可能な値の範囲内です）。

#### ✅ 検証6：予測は可能。ただし2段構えになる

```
全都 小学校1年生数の推計（教育庁 25es_result01）
R7 93,532（実数）→ R12 76,342 → R13 76,616 → R15 75,694 → R20 78,373
                    └ 区市町村別はここで切れる ┘  └─ 全都はここまである ─┘
```

| 入学年度 | 子の現在年齢 | 根拠 | 性質 |
|---|---|---|---|
| **令和9〜13年度（2027〜2031）** | 1〜6歳 | **区市町村別の都の公式推計そのもの** | 最も硬い |
| **令和14〜20年度（2032〜2038）** | 0歳〜未出生 | **全都の公式推計の伸び率**を区市町村のR12値に接続 | **都の公式数字2つを接続した推定。区ごとの伸びの差は失われる** |
| 令和21年度以降 | — | 根拠なし | **やらない** |

**「自前で外挿した」ではなく「都の公式推計どうしを接続した」と言えます。**
画面で境界線を引き、2段目は予測区間を広げます。

#### ✅ 検証7：予測精度を実測済み

令和5年度版の推計が出した令和7年度値 vs 令和7年度実数（57地区）：

```
平均誤差 +0.26% / 中央値 +0.50% / 絶対誤差平均 1.51%
最大の外し：島部 -6.02% / 国立市 -5.57% / 東大和市 +4.13% / 日の出町 +5.18%
```

> ⚠️ **実測できるのは1年先と2年先だけ**です（推計ヴィンテージが令和5・6・7の3世代しかない）。
> **それ以降は外挿だと明記します。測っていないことを測ったように書かない。**
> 家の購入判断に使わせる以上、これは最低条件です。

### 1-3. 修正後の仮説

**課題仮説・顧客セグメント仮説は維持。ソリューション仮説を3点修正します。**

| | 当初 | 修正後 |
|---|---|---|
| 主指標 | 待機児童数ベースの簡易指標 | **登録率（登録÷児童数）を主、待機児童数を補助** |
| 時点 | 現在の集計 | **子が小1になる年度の予測値**（都の公式推計を軸に） |
| 外れ値 | （未定義） | **制度差／本物の不足／母数不足を区別して注記** |

粒度は**区・市町村単位**のまま（仮説どおり）。学校単位のデータは
**需要の母数を精緻にするために内部で使い**、画面では自治体単位に集約します。

## 3. 提供価値

> **取り返しのつかない意思決定を、間違えないこと。**

住宅ローンを組んだ後では動けません。この一点に価値があります。

**予測を見た人が打てる手**（これが無いと不安を煽るだけになるので、**画面に必ず出します**）：

- 検討している街を選び直す（近隣自治体と比較する）
- 住み替えの時期を、入学年度に合わせてずらす
- 民間学童の費用を、最初から資金計画に織り込む
- 保育園を選ぶ段階で、学童併設・学校併設を条件に入れる

> ⚠️ **「◯時間削減」を根拠なく書かないこと。**
> 本サービスの価値は「調べる時間の短縮」ではありません。そう書いた方が強く、かつ正直です。

## 4. スコープ

### やること（v1）

- **軸1（学童）の将来リスクを49自治体でスコア化**し、**ヒートマップ**で表示する
- 自治体を選ぶと詳細（登録率の推移・予測区間・待機児童数・注記・打てる手）を表示
- **自然文シナリオ**を入力すると再計算する
- **出典とライセンス表記**を画面に出す
- **軸を後から追加できる構造**にしておく（プラグイン化）

### やらないこと（意識的に捨てる）

**⛔ 以下は v1 で作りません。時間はすべて軸1の完成度に注ぎます。**

| 捨てるもの | 理由 |
|---|---|
| 地図表示 | ジオコーディングAPIが CONNECT 403。自治体単位MVPに不要 |
| ログイン・ユーザー登録 | デモに不要 |
| 通勤時間 | 経路探索が要り1.5日では重い。**軸2・3の受け口だけ用意** |
| 住宅価格帯 | 国交省APIのキー申請が締切に間に合うか不明。同上 |
| 学区単位の表示 | 受け入れ枠が区単位でしか無い（検証5） |
| 軸2・軸3の中身 | **構造だけ定義し、中身は後で決める**（決定済み） |
| レスポンシブの作り込み | 審査は動画。想定画面幅を1つ決めて集中する |
| データベース・KV | データが455KB（gzip150KB）で不要（`docs/14-basic-design.md` §1） |

### 対象範囲

**23区 ＋ 多摩26市 ＝ 49自治体。**

**島嶼部・郡部（町村）は除外します。** 母数が小さく比率が壊れるためです
（実測：利島村の登録率1.455／三宅村1.431／母数はそれぞれ11人・51人）。

## 5. ユースケース（1本だけ）

**⛔ 2分動画で映るのはこの1本です。これ以外のシナリオは設計しません。**

> **UC-1：2歳の子がいる共働き夫婦が、購入候補エリアの学童リスクを比べる**
>
> 1. 子の生まれ年（2024年）を入力する → **小1になるのは2031年度**と決まる
> 2. 49自治体のヒートマップが表示される。**行＝自治体、列＝入学年度、セル色＝リスク**
> 3. 検討している自治体（例：杉並区）をクリックする
> 4. 登録率の推移（実績＋予測）・予測区間・待機児童数257人・注記が出る
> 5. **打てる手**が出る（近隣自治体との比較・時期をずらす・民間学童の予算）
> 6. 「駅前に600戸のマンションが2028年に完成する」と自然文で入力すると、
>    **都の公式係数（住宅種別×学年別の児童発生率）で再計算される**

## 6. 機能要件（FR）

| ID | 要件 | 優先 |
|---|---|---|
| **FR-1** | 子の生まれ年から**小1になる年度を決定**する。射程外の年度は §1-2 検証6 の区分を明示する | 必須 |
| **FR-2** | 自治体ごとに**軸1のリスクスコア（0〜100）**を、入学年度別に算出する | 必須 |
| **FR-3** | **49自治体 × 入学年度のヒートマップ**を表示する。セル色＝スコア | 必須 |
| **FR-4** | 自治体を選ぶと**詳細**（登録率の実績と予測・予測区間・クラブ数・登録児童数・待機児童数）を表示する | 必須 |
| **FR-5** | **注記を表示**する。制度が別枠（江戸川区）／本物の供給不足（中央区）／母数不足 を**区別**する | 必須 |
| **FR-6** | **打てる手**を表示する（近隣自治体の比較を含む） | 必須 |
| **FR-7** | **自然文シナリオ**を入力すると、都の公式係数に変換して再計算する | 推奨 |
| **FR-8** | **出典・提供元・ライセンス・取得日**を画面に表示する | **必須（大会ルール）** |
| **FR-9** | **軸を追加しても画面とスコア計算が壊れない構造**にする（指標プラグイン） | 必須 |
