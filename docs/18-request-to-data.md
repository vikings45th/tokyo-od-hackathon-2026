| `gakudo[]`（3時点） | 学童クラブ実施状況 | ✅ CSVにある |

| **`children2023`**（令和5年度の全学年実績） | **公立学校一覧 令和5年度** | ⛔ **無い** |

加えて `AppData` としては `schools[]` / `tokyo`（全都・令和7〜20）/ `backtest[]` /
`sources[]` が要ります。**形は `data/sample.json` とまったく同じ**です

### 置き場所の相談 🔴

**`data/app/` の直下には、公開してよいファイルだけを置いてください。**

②の `vite.config.ts` は今 `publicDir: false` になっています。理由はコメントに
書いてあるとおりで、`data/` 直下には**転載不可のPDF・CSV**が置かれており、
`publicDir: '../data'` にすると**まるごと `dist/` にコピーされて公開URLから配信**されます。

`data/app/` に `data.json` だけ（＋③が置く `tokyo-49.topo.json`）を置ければ、
`publicDir: '../data/app'` の1行変更で安全に配信できます。

```
data/
  app/            ← ✅ 公開してよいものだけ。ここが dist/ にコピーされる
    data.json           （①）
    tokyo-49.topo.json  （③がコピーします）
  raw/            ← .gitignore 済み
  processed/      ← 中間生成物。公開しない
  *.pdf           ← 🔴 転載不可。絶対に app/ に入れない
```

### `sources[]` は手を抜かないでください

提出フォームの**エントリー項目⑤で最大10件の記入が必須**です（`docs/01-event.md`）。
`data/SOURCES.md` に書いてある内容を、そのまま `AppData.sources` に入れてください。
**③はこれを画面のS5「根拠と出典」にそのまま出します**（FR-8・大会ルール）。
`name` / `provider` / `license` / `url` / `retrievedAt` の5つ全部が要ります。

## 依頼2【重要】生成AIを前処理で1回だけ回して、結果をコミットする

### 状況

設計書 `docs/14-basic-design.md` §7 で決めた**生成AIの3か所のうち、
実装されているものが今ゼロ**です。

| # | 用途 | 担当 | 現状 |
|---|---|---|---|
| ① | 様式不定CSVの読解ETL | ① | ⛔ `scripts/build_processed.py` は `MUNI_CODE` 直書きの手書きパーサ |
| ② | 自然文シナリオ → パラメータ変換（実行時） | ② | ⛔ **v1では作らないと決定**（下記） |
| ③ | 制度差・外れ値の注記文 | ① | ⛔ 未着手 |

このままだと提出フォームの**エントリー項目③「生成AI等の活用方法」に
書ける実装がありません。** 審査基準「技術力」に直結します。

②の実行時LLM（`/api/scenario`）は、**チームとして落とすことを決めました。**
理由は Workers AI のクレジットが**チーム$100・追加は承認制**であること、
Cloudflareライセンスが**申請から発行まで1週間程度**かかる見込みで 8/23 に
間に合わない可能性があること、そして「**数値を作るのは都の公式係数であって
LLMではない**」という設計を崩さないためです。②はプリセット5件に置き換えました。

→ **①の2用途が、提出項目③に書ける唯一の実装になります。**

### 何をやるか

**どちらも前処理で1回だけ**です。Cloudflareライセンス待ちにも $100 上限にも
依存しません。`CLAUDE.md` の「前処理でLLMを走らせて結果をコミットしておく方が安全」
にそのまま沿います。

#### 用途① — 様式不定CSVの読解ETL

CSVの**先頭30行だけ**をLLMに渡し、**抽出プランJSON**を作らせます。

```jsonc
// scripts/plans/gakudo_2025.json（コミットする）
{
  "headerRow": 6,
  "blocks": [ {"name": "区部", "colStart": 1}, {"name": "市町村部", "colStart": 9} ],
  "columns": { "muni": 1, "clubs": 3, "registered": 4, "waiting": 5 },
  "numberCleaning": ["strip", "removeComma", "emptyOrDashToNull"]
}
```

決定論的なパーサがこのプランを実行します。
🔴 **LLMは値に触りません。プランだけ作ります。**
だからハルシネーションが数値に混入しません。**この一文がそのまま提出項目③になります。**

なぜルールベースで書けないのか：学童はヘッダ6行目・区部と市町村部が横並び2ブロック・
数値は `"1,261 "` 形式、学校一覧は多階層ヘッダで欠測が `-`、推計は縦持ち＋和暦列。
**局ごとに様式が違い、毎年変わります。**
`docs/13-requirements.md` §1-2 検証4 で「そのままでは読めない」と主張している
当の問題を、AIで解いていることになります。

#### 用途③ — 制度差・外れ値の注記文

`Note.text`（`src/types.ts`）を作ります。**②の判定ロジックはもう動いています**
（`src/core/notes.ts` が `kind` を出します）。足りないのは**文面**です。

実測で必ず出るのはこの3種です：

| 自治体 | kind | 実測 |
|---|---|---|
| 江戸川区 | `series-break` | 2023-05 は 4クラブ/141人 → 2025-05 は 72クラブ/6,623人 |
| 中央区 | `real-shortage` | 2025-05 登録1,291人・待機275人・顕在需要率0.163 |
| 利島村など | `small-sample` | 母数11人 |

数値ルールでは全部「異常値」としか言えません。
**江戸川区（計上方法が変わっただけ）と中央区（本物の供給不足）の違いは、
各区の制度を読まないと分かりません。** ここがLLMの仕事です。

🔴 **江戸川区を「異常値だから除外」と書かないでください。**
②の実装は `series-break` を**トレンド計算からのみ除外**し、スコアには含めています。
文面もそれに合わせてください。

### 終わったら

`docs/11-ai-log.md` に**その場で1行**追記してください。
使ったモデル・入力・出力・なぜAIが必要だったかを書けば、
そのまま提出フォームのエントリー項目③になります。あとでまとめようとすると必ず漏れます。

⚠️ **APIキーはソースにも環境変数欄にも書かないでください。**
クラウド環境の環境変数欄は「anyone who uses the environment can read the values」と
公式ドキュメントに明記されています（`CLAUDE.md`）。
