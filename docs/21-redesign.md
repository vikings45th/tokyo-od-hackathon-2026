## 1. デザインコンセプト

> **「東京都の統計を触っている感じ」を、最初の1秒で出す。**

読ませてから触らせるのではなく、**触れる面の上に文章を寄せる**。
地図・年度・選択自治体の数字は**スクロールしても画面から消えない**。文章は
その計器の横を流れていく副音声で、主役ではない。

3つのルールでこれを担保する。

| ルール | 何のためか |
|---|---|
| **画面には常に、操作できる面と結果の数字が同時にある** | 「資料」ではなく「道具」に見せる |
| **年度は画面全体で1つの時計。地図もランキングもヒートマップも同じ年度を見る** | 表示が食い違った瞬間、データの信用が全部消える |
| **箱を使わない。区切りは余白と1pxのヘアラインだけ** | 既存資産の踏襲。角丸＋左ボーダー＋薄グラデのカードは使わない |

## 2. 情報設計 — 現行6セクションとの差分

### 2-1. 何が「パワポっぽさ」だったのか（依頼で示された3点）

1. `#s0`〜`#s2` に `min-height:100vh`。1画面＝1枚で完結し、スクロールが「めくる」動作になっていた
2. 6セクションが全部同じ型（eyebrow → 見出し → リード → 中身）。スライドマスターの使い回しと同じ律動
3. 触れる面（S4）が5番目。ヘッダーも固定要素も無く、「これは読み物です」という信号しか出ていなかった

### 2-2. どう構造で解いたか

**装飾を足していない。セクションという単位そのものを解体した。**

新しい骨格は3つしかない。

```
┌──────────────────────────────────────────────────────────┐
│ .bar   固定ヘッダ（58px）                                  │  ← 常に見える
│        小1の壁マップ │ 子の生まれ [2024年][6月] → 小1は 2031年度 │ 精度 出典 DARK │
├───────────────────────────────┬──────────────────────────┤
│ .inst  計器列（sticky・100vh）  │ .rail 解説列（流れる）      │
│                               │  ┌ .railnav（sticky・現在地）│
│   ┌───────────────────┐       │  ├ #lede    はじめに        │
│   │   コロプレス地図    │       │  ├ #rank    順位           │
│   │   （クリック/ズーム）│       │  ├ #muni    この自治体      │
│   └───────────────────┘       │  ├ #story   この先          │
│   ── 年スクラバ 2027〜2038 ──  │  ├ #heat    12年度の表      │
│   中央区 2031年度               │  ├ #scenario 条件          │
│   882 人が、入れない            │  ├ #evidence 精度          │
│   必要 2,173 / 受入 1,291 / …   │  └ #sources  出典          │
│   出典：東京都教育庁・福祉局…    │                            │
└───────────────────────────────┴──────────────────────────┘
```

**旧セクションの行き先（＝差分）**

| 旧 | 新 | 「パワポっぽさ」のどれを消したか |
|---|---|---|
| **S0 ヒーロー**（`min-height:100vh`・地図ゴースト・SCROLL 指示） | 消滅。名乗りは **`.bar`（常設）**、コピーは解説列の先頭パネル `#lede` | **①** 全画面の表紙が無くなった。**③** 主入力（子の生まれ）がヘッダに上がり、地図は最初のフレームから実物 |
| **S1 タイムライン**（`min-height:100vh`） | `#lede` の中の高さ74pxのライブ年表（2026 →〈N年〉→ 小1の年） | **①** 1枚が1行になった。**②** 独立セクションではなく「入力の説明」になった |
| **S2 巨大な数字**（`min-height:100vh`・260pxの数字1つ） | **`.inst` の結果帯**。選択と年度に追従して常時更新（数字は clamp(40,3.8vw,62)） | **①②③** 「1枚で1つの数字」が「消えない計器の一部」になった。数字が**動く**ので読み物に見えない |
| **S3 スクロール物語**（`height:340vh`・**別の地図**・空の step div） | **年スクラバ**（掴める）＋ 解説列の `#story`（1段62vh・文章入り）。動かすのは**同じ地図** | **①** 340vh が消え、次の段が常に視界に入る高さにした。物語は**操作子に畳まれて残った** |
| **S4 ツール**（5番目） | **画面そのもの**。地図・ランキング・詳細・ヒートマップ・条件に分解して配置 | **③** 位置が5番目から0番目に |
| **S5 根拠・出典** | `#evidence` `#sources` ＋ **`.inst` の常設クレジット**（1行）＋ ヘッダの「精度／出典」リンク | **③** 出典が画面から消える瞬間を無くした（FR-8 の担保が強くなった） |

### 2-3. 「同型の反復」を潰した方法

パネルは**わざと形をそろえていない**。

- `#lede` … 文章（h1 は他パネルの2倍の級数）
- `#rank` … 10行のリスト＋バー
- `#muni` … 注記 → 折れ線グラフ → 丸ボタン → 箇条書き
- `#story` … 62vh の段が3つ。見出しも eyebrow も無い
- `#heat` … 12列のマトリクス
- `#scenario` … ボタンの列 ＋ 折りたたみ
- `#evidence` … 数字3つ
- `#sources` … ライセンス別のリスト

**共通しているのは「上に1pxのヘアライン、左に小さなラベル」だけ**で、これは
スライドマスターではなく**資料の付表の書式**。しかも左に地図が居座っているので、
1パネル＝1画面という読み方が物理的に成立しない。

さらに、**旧版の `.rise`（スクロールでフェードイン）を全廃した。**
順番に現れる演出そのものが「めくる」感覚の主犯なので、装飾ではなく除去で対応している。
動きが残るのは `#story` の段の不透明度だけ（`prefers-reduced-motion` で無効化）。

### 2-4. 物語を消さなかった理由と、残し方

「詰むのは6年後」が入口である以上、物語は要る。ただし**別の場所に別の地図を置く**のをやめた。

- 年度は `viewYear` という**1つの state** に集約した
- 既定値＝あなたの子が小1になる年度
- `#story` をスクロールすると段ごとに `viewYear` を上書きし、**左の地図が動く**
- 物語の外（先頭・末尾の段）に出ると、自動で自分の子の年度に戻る
- **同じ値をスクラバでも掴める**。物語は「自動再生されるスクラバ操作」でしかない

結果、物語は**道具の使い方のデモ**になった。読み物から道具への転換を、
コンテンツを削らずに達成している。

## 4. 配色・タイポ・余白・コンポーネント

### 4-1. 引き継いだもの（変更なし）

- **`src/ui/palette.ts` は1文字も触っていない。** 5段ランプ・ink・nodata すべて据え置き
- 配色トークン：`--accent #1c5cab`／地 `#ffffff #fcfcfb #f4f4f2`／文字 `#0b0b0b #52514e #8a8983`／罫 `#e6e6e1`／`--warn #b06a00` `--crit #c23434`／ダークテーマ一式
- タイポ：`-apple-system, "SF Pro Display", "Hiragino Sans", "Noto Sans JP"`、本文15px/1.6、`font-feature-settings:"palt" 1`、見出し800・字間 -.035〜-.055em、数字は `font-variant-numeric:tabular-nums`
- **「箱を使わない」**：枠線＋影のカードはゼロ。区切りは余白と1pxヘアラインのみ

**コントラスト制約は守っている。** 最淡 `#86b6ef` が載る面は
地図＝`--bg-0 #ffffff`（2.11:1 PASS）、ヒートマップ＝同じく `--bg-0`。
**セクション背景をグレーにしていない**（旧 `#s4` の `--bg-1` すら外し、作業面は白一色にした）。

### 4-2. 足したトークン

| 追加 | 値 | 理由 |
|---|---|---|
| `--bar-h` | `58px`（≤1000で52px／≤600で84px） | 固定ヘッダの高さ。`position:sticky` の `top` 基準を1か所にまとめる |
| `--gut` | `36px`（26 / 18 / 14） | ページ左右の余白 |
| `--col-gap` | `34px` | 計器列と解説列のあいだ |
| `--rail` | `498px`（≤1280で400px） | 解説列の幅。1440px 主戦場で地図に約780pxを残す実測値 |
| `--fs-lede` | `clamp(27px,2.6vw,42px)` | `#lede` の h1。旧 `--fs-hero`（最大88px）の**置き換え**。表紙にしないため級数を落とした |
| `--fs-result` | `clamp(40px,3.8vw,62px)` | 結果帯の数字。旧 `--fs-num`（最大260px）の置き換え。常設なので画面を占有しない大きさに |

**削除**：`--fs-hero` `--fs-num` `--fs-sect` `--ghost-op`（S0のゴースト地図ごと廃止）。

### 4-3. UIコンポーネントの方針

- **押せるものと押せないものを見た目で分ける。** `.act`（丸・枠線・ホバーで濃くなる）＝押せる／
  `.advice` `.advices`（枠なし・地の文）＝読むだけ。旧版から継続
- **ボタンは3種類だけ**：`.zb`（小さい操作・角丸8px）／`.preset` `.act` `.more-btn`（丸・999px）／
  `.preset.on`（塗り）。角丸の値を増やさない
- **ツールチップは自前の `.tip`**（native `title` では読ませたい文が長すぎる）。
  `tabIndex` を持たせてキーボードでも開く
- **凡例・注記は必ずデータの隣に置く**。推定区間の断り書きはヒートマップの直下、
  根拠区分バッジは年スクラバの隣

## 5. PC とスマホのレイアウト方針

| 幅 | 方針 |
|---|---|
| **〜1560px（主戦場 1440px）** | 2列グリッド `minmax(0,1fr) 498px`。計器列 sticky。地図に約780px（実測でSVG 900×520が余裕を持って収まる） |
| **〜1280px** | 解説列を400pxに。ヘッダの副題（`東京都オープンデータ ／ …`）を落とす。ヒートマップのラベル列 96→62px。解説列ナビは横スクロールさせず**折り返す** |
| **〜1000px** | 1列。**`.inst` を `display:contents` にして、地図＋年スクラバだけを sticky にする**。結果帯と出典は普通に流す（結果帯まで貼り付けると画面の半分が埋まるため）。地図は `aspect-ratio:900/520` で縦の無駄を出さない |
| **〜600px** | ヘッダを**2段**（上＝名前とテーマ／下＝主入力）。390px幅では1行に入らないので、要素を消すのではなく段を増やす。`--bar-h:84px` |

> 🔴 **スマホの地図には `touch-action:pan-y` を当てている。**
> PCと同じ `touch-action:none` のままだと、画面の上半分に貼り付いた地図の上で
> 縦スワイプが吸われて**ページが1ミリも動かなくなる**。横ドラッグでの地図パンは残る。
> あわせて `onPointerCancel` を足した（ブラウザにスクロールを奪われたとき
> `pointerup` が来ず、掴みっぱなしになるため）。

実機確認は**まだ取れていない**（`[要確認]`）。上記は Chromium 390×844 / 1280×800 / 1440×900 の
スクリーンショット実測に基づく。iOS Safari の `position:sticky` ＋ `aspect-ratio` は
挙動が異なる可能性がある。
