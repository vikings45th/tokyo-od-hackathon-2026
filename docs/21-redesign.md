## 0. この版に至った経緯

**第1版**（旧6セクション → 固定ヘッダ＋左に凍結した計器列＋右に流れる解説列）で
「パワポっぽさ」（`min-height:100vh` の反復・同型セクション・触れる面が5番目）は解消できた。
だが**行き過ぎてダッシュボードになった。**

> 左が止まって右だけ動く構造が分かりにくい。ダッシュボードにしたいわけじゃない。
> LP的なコピーと、地図＋ヒートマップという道具の機能が混在していて、
> 1枚のウェブページとしてどういう作りにすればいいかがぶれている。

**原因はレイアウト調整ではなく、LPと道具を「空間で並べた」こと自体。**

- ダッシュボードは「毎日開いて、自分が何を探しているか既に知っている人」の形。
  このサービスの読者は真逆で、`docs/20-service-canvas.md` にあるとおり
  **「知っている側が、知らない側に見せる」1回きりの画面**（「小1の壁」の認知は
  共働きママ 64.1% ／ パパ 2割台）。同時に全部を出すと、どこから見ればいいか決まらない。
  → **同時性ではなく順番で解くべきだった。**
- 混在自体は悪くない。LPがアイデア力・ソーシャルインパクトを、道具がデータ活用・技術力を担う。
  悪いのは**いま自分がどちらのモードにいるかの合図が無い**こと。
- 第1版は依頼文「操作できる面が常にある構造を借りる」を literal に取りすぎた。
  元の不満は「触れる面が**5番目に埋もれている**」であって「常時見えていてほしい」ではない。
  **上から4番目（スクロール2回）に置けば足りる。**

## 1. デザインコンセプト

> **1本の縦スクロールで、読者を「読む」から「使う」へ手渡す。**
> モード転換の合図は**幅**で作る。凍結ペインは使わない。

```
.read  660px 中央寄せ  #lede → #why → #ask          読む
──────────────────────────────────────────────  ← ここで幅が変わる
.wide 1360px          #tool → #muni → #heat → #scenario   使う
──────────────────────────────────────────────  ← ここで幅が戻る
.read  660px          #evidence → #sources          確かめる
```

幅が変わること自体が「ここから道具です」の宣言になる。読者は何も説明されなくても分かる。
**切り替わりは1往復だけ**（読む → 使う → 読む）。交互に出すと元の「同型反復」に戻る。

**蝶番は `#ask` の生まれ年入力。** ここで「一般の話」が「あなたの話」になる。
`docs/20-service-canvas.md` の検査項目「誰にでも当てはまることを書くな／常に読者の固有の
状況に接地させる」が、そのまま構造になっている。

ペインではなく**ツールバー**。ダッシュボードには見えない。

`地図で調べる ↓`（`#tool` へ）／`精度`／`出典`／テーマ切替。

### 主なコンポーネント方針

- **押せるものと押せないものを見た目で分ける。** `.act`（丸・枠線・ホバーで濃くなる）＝押せる／
  `.advice` `.advices`（枠なし・地の文）＝読むだけ
- **結果は「箱」ではなく罫だけの明細**にする（`.result .facts` は `border-top` の行の連なり）
- **セクションの罫は全幅。** `<section>` に `border-top` を引き、中身だけ `.read`/`.wide` で絞る。
  端から端まで走る1本の線が、モードの切れ目を示す
- ツールチップは自前の `.tip`（native `title` では読ませたい文が長すぎる）。`tabIndex` でキーボードでも開く
