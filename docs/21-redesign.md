## 1. デザインコンセプト

> **1本の縦スクロールで、読者を「読む」から「使う」へ手渡す。**
> モード転換の合図は**幅**。凍結ペインは使わない。

```
.read  660px 中央寄せ  #lede → #why → #ask                          読む
─────────────────────────────────────────────────  ← ここで幅が変わる
.wide 1360px          #tool → #choose → #muni → #heat → #scenario   使う
─────────────────────────────────────────────────  ← ここで幅が戻る
.read  660px          #evidence → #sources                          確かめる
```

幅が変わること自体が「ここから道具です」の宣言になる。**切り替わりは1往復だけ**
（読む → 使う → 読む）。交互に出すと元の「同型反復」に戻る。

**蝶番は `#ask` の生まれ年入力。** ここで「一般の話」が「あなたの話」になる。
`docs/20-service-canvas.md` の検査項目「誰にでも当てはまることを書くな／常に読者の固有の
状況に接地させる」が、そのまま構造になっている。

## 2. 「パワポっぽさ」と「ダッシュボードっぽさ」を、どちらも避けている根拠

| 避けたいもの | どう抑えているか |
|---|---|
| **1画面＝1枚（めくる感じ）** | `min-height:100vh` を作らない。`#lede` だけ `52vh` で、ファーストビューに必ず次のセクションの頭が入る |
| **同型セクションの反復** | 型は `.read`（本文幅・散文）と `.wide`（全幅・図版）の2つだけ。`eyebrow → 見出し → リード → 中身` の反復はやめ、大見出しは各セクション1本（`h1` は `#lede` のみ） |

| **ダッシュボード（凍結ペイン）** | sticky を1つも使わない。`#tool` の地図も普通に流れる |

### 使う（`.wide` 1360px）

#### `#tool` — 地図が一番の見せ場


  `.selbar` はクリックの**フィードバック**なので、必ず見える位置に置く

#### `#choose` — 「じゃあ、どこに住めばいいか。」（第3版で新設）

```
secthd: h2「じゃあ、どこに住めばいいか。」... meta「{firstYear}〜{lastYear}年度のどの年も不足しないのは ◯自治体」
┌ 左：{sel}の近くなら ──────────┬ 右：全員入れる期間が長い順 ─────────┐
│ 選択自治体（いま見ている）＋      │ 上位10。ボタンで「いま厳しい順」に切替  │
│ 隣接自治体を全件、良い順に        │                                     │
│ 行＝自治体名／最初に不足する年度／ │ 行＝順位／自治体名／最初に不足する年度／ │
│    {viewYear}年度に入れない子（人）│    {viewYear}年度に入れない子（人）    │
└───────────────────────────┴─────────────────────────────┘
注記：この順位は学童の受け皿だけを見たものです。通勤時間・家賃・保育園は含んでいません。
```

**並べ替えの指標（第3版で新設）**

素直に「入れない割合が低い順」を出すと、**下位に 0% が大量に並んで順位にならない**
（上位は 41 / 13 / 12 …だが、下に行くほど 0 が連続する分布）。そこで：

> **最初に不足が出る年度** — その自治体で `detail.gap >= 1`（入れない子が1人以上）になる最初の年度。
> 最後まで出なければ「{lastYear}年度まで、どの年も全員入れる」。

同着は「最終年度のスコア昇順 → 最終年度の余裕人数（`supply − demand`）降順 → 名前」で割る。
これで 0% 同士にも差が付き、実測でも **{lastYear}年度まで全員入れるのは数自治体**まで絞り込める。

⚠️ 言い回しは **「最初に不足するのは ◯◯年度」**にしてある。「◯◯年度から先ずっと不足する」ではない
（需要は年で上下するので、いったん不足してから戻る自治体がある）。
また `Math.round(gap) >= 1` ではなく **`gap >= 1`** で判定している。0.6人を1人に丸めると
モデルの分解能を超えた主張になるため。

⚠️ 右端の数字は **% ではなく人数**。数人の不足は四捨五入で 0% になるので、
「最初に不足するのは2027年度」の隣に「0%」が並んで矛盾して見える。

> 🔴 **単軸しかないので「総合おすすめ度」は名乗らない。** 通勤時間も住宅価格も持っていない
> （`docs/13-requirements.md` §4 で意識的に捨てた軸）。画面に断りを必ず出す。

### 🔴 `src/ui/hooks.ts` — 地図クリックが効かなかったバグの修復

**症状**：地図上のどの自治体を押しても選択が変わらない（49件すべて）。

**原因**：`useZoomPan` が `pointerdown` の時点で `setPointerCapture` していた。
捕獲すると続く `pointerup` の target が `<path>` ではなく `<svg>` になる。
`click` は pointerdown と pointerup の**共通祖先**に発火するので `<svg>` で発火し、
自治体 `<path>` の `onClick` が一度も呼ばれない。**ドラッグ機能を足したときにクリックを潰していた。**

**修正**：動き始めてから捕獲する。

```ts
/** これ以上動いたらドラッグ。これ未満はクリック（自治体の選択）として扱う */
const DRAG_SLOP = 4;

const onPointerDown = (e) => {
  // 🔴 ここで setPointerCapture してはいけない（上記の理由）
  drag.current = { x: e.clientX, y: e.clientY, vx: vb.x, vy: vb.y, captured: false };
};
const onPointerMove = (e) => {
  const d = drag.current; if (!d) return;
  if (!d.captured) {
    if (Math.hypot(e.clientX - d.x, e.clientY - d.y) < DRAG_SLOP) return;
    e.currentTarget.setPointerCapture(e.pointerId);
    d.captured = true;
  }
  … 既存のパン処理 …
};
```

**検証済み**（Playwright・`vite preview`）：

| | 修正前 | 修正後 |
|---|---|---|
| 地図の自治体をクリック | 選択が変わらない ❌ | 中央区 → 千代田区 ✅ |
| `.selbar` / `#choose` 左 / ヒートマップ先頭行 / 地図の選択リング | — | すべて追従 ✅ |
| 拡大後に90px ドラッグ | viewBox が動く ✅ | viewBox が動く／選択は変わらない ✅ |

### 🟢 `src/ui/Choropleth.tsx` ＋ `geo.ts` — 全体表示でも自治体名を出す（第4版・C）

以前は `scale >= 1.55` でしか出していなかった（「全体表示で49件出すと潰れる」）。
**それは地図が細い列に入っていた頃の前提**で、全幅にした今は成立しない。

拡大率でゲートするのをやめ、**重なりだけを貪欲法で避ける**：

1. 選択中の自治体を最優先（クリックのフィードバックなので必ず出す）
2. あとは面積の大きい順（`geo.ts` に `MuniShape.area` を追加。d3-geo の `path.area`）
3. 既に置いた枠と重なるものは飛ばす。拡大すると枠が相対的に小さくなり、自然に出てくる

⚠️ 枠は実際の文字より**少し大きく**取る（太字で幅が伸び、縁取り `strokeWidth 3/scale` が
左右に出るため）。小さく見積もると重なる。**実測：1440×900 の全体表示で 46/49 件・重なり0件。**

⚠️ スマホでは CSS で消している（390px幅だと画面上4px相当になり読めない）。
